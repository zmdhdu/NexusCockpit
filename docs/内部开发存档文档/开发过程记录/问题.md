## 四、正式配置 vs 独立 dev 调试配置分离方案

### 文件分层架构

```
NexusCockpit/
├── .env                        ← 交付版模板 (tracked, 无密钥)
├── .env.local                  ← dev 调试配置 (gitignored, 含 dev 密钥)
├── .env.prod                   ← 生产环境配置 (gitignored, 含 prod 密钥)
├── .env.prod.example           ← 生产模板 (tracked, 无密钥)
├── docker-compose.yml          ← 交付版编排 (无调试端口)
├── docker-compose.dev.yml      ← dev 调试覆盖 (调试端口/挂载)
```

### 配置加载逻辑（config.py 自动选择）

| APP_ENV | 加载文件 | DEBUG | LOG_LEVEL | CORS | RBAC 角色 |
|---------|---------|-------|-----------|------|----------|
| `local` (默认) | `.env.local` | `true` | `DEBUG` | `*` | `super_admin` |
| `prod` | `.env.prod` | `false` | `WARNING` | 指定域名 | `cockpit_user` |

### Docker 启动方式

```bash
# 交付版（仅必需端口）
docker compose --profile app up -d

# 开发调试版（含调试端口: Neo4j Browser, Grafana, Prometheus, Loki 等）
docker compose -f docker-compose.yml -f docker-compose.dev.yml --profile app up -d
```

## 八、用户需手动处理的事项

以下因文件已 gitignored 或涉及真实密钥，需您手动处理：

1. **`.env.prod`** — 请参考 `.env.prod.example` 重写，填入生产环境真实值
2. **`.env.secrets`** — 建议将其中密钥合并到 `.env.local`，然后删除此文件
3. **`.env.example`** — 与 `.env` 内容重复，建议 `git rm .env.example` 删除
4. **RBAC_ADMIN_PASSWORD / RBAC_USER_PASSWORD** — `.env.local` 和 `.env.prod` 中需手动设置强密码（Go 网关需要）
5. **Docker 默认密码** — 交付时在 `.env.prod` 中设置 `MINIO_ACCESS_KEY/MINIO_SECRET_KEY`、`GRAFANA_ADMIN_PASSWORD`、`LANGFUSE_NEXTAUTH_SECRET/LANGFUSE_SALT`
