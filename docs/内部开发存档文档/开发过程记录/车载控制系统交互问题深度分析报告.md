### P1: 音频控制模块故障 — "关闭音乐"执行了 `play`

> ✅ **已修复** — `heuristic.py` 第 261 行已扩展 pause/stop 关键词列表

#### 复现步骤

1. 用户输入: `"关闭音乐"`
2. 日志输出:
   ```
   Sandbox audit: tool=vehicle_media, status=ok, args={'op': 'play', 'source': 'local', 'track': ''}
   Vehicle command verified OK: vehicle_media
   ```
3. 实际行为: 执行了 `op=play`（播放音乐）
4. 预期行为: 应执行 `op=pause` 或 `op=stop`（暂停/停止音乐）

#### 根因定位（修复前代码）

文件: `backend_design/nexus/intent/heuristic.py`

修复前 `_extract_media` 方法中，pause/stop 关键词列表仅有 `("暂停", "停止")`，`"关闭"` 不在其中，导致 `"关闭音乐"` 落入 `else: op = "play"` 默认分支，产生反向执行。

**问题链**:
1. 用户输入 `"关闭音乐"` → 去空格后仍为 `"关闭音乐"`
2. 入口条件匹配: `"音乐"` 在关键词列表中 ✓
3. 操作判断: `"关闭"` 不在 `("暂停", "停止")` 中 ✗
4. 落入 `else: op = "play"` → **反向执行**

**缺失关键词**: `"关闭"`, `"关掉"`, `"关了"`, `"别放了"`, `"别唱了"`, `"关音乐"` 等自然表达均未映射到 `pause`/`stop`。

#### 修复后代码（当前状态）

文件: `backend_design/nexus/intent/heuristic.py` 第 256-277 行

```python
def _extract_media(self, text: str) -> dict[str, Any]:
    if not any(k in text for k in ("音乐", "播放", "暂停", "停止", "下一首", "上一首", "音量", "切歌", "听歌", "歌曲", "歌")):
        return {}

    # P1 修复: 扩展暂停/停止关键词，覆盖"关闭音乐""关掉音乐""别放了"等自然表达
    if any(k in text for k in ("暂停", "停止", "关闭", "关掉", "关了", "别放", "别唱", "关音乐", "停止播放", "静音")):
        op = "pause"
    elif any(k in text for k in ("下一首", "下一曲")):
        op = "next"
    elif any(k in text for k in ("上一首", "上一曲")):
        op = "prev"
    elif any(k in text for k in ("播放", "放音乐", "听歌", "听音乐", "放首歌", "来首")):
        op = "play"
    else:
        op = "play"

    volume = None
    vol_match = re.search(r"音量(\d{1,2})", text)
    if vol_match:
        volume = int(vol_match.group(1))

    return {"Media_Action": {"op": op, "source": "local", "track": "", "volume": volume}}
```

### P2: 意图路由错误 — "将空调开到27度"被误识别为导航意图

> ✅ **已修复** — `heuristic.py` 第 223-239 行已增加空调语境排除逻辑

#### 复现步骤

1. 用户输入: `"将空调开到27度，两级风速"`
2. 日志输出:
   ```
   Multi-intent detected: extractors=['_extract_climate', '_extract_navigation'],
   intents=['Climate_Action', 'Navigation_Action'], text='将空调开到27度，两级风速'
   ```
3. 实际行为: 同时触发 `vehicle` 和 `navigation` 两个专家
4. 预期行为: 仅触发 `vehicle` 专家

#### 根因定位（修复前代码）

文件: `backend_design/nexus/intent/heuristic.py`

修复前 `_extract_navigation` 方法中，`nav_keywords` 包含 `"开到"`，且正则 `(开到)([^，。！？?]+)` 会将 `"开到27度"` 匹配为导航目的地 `"27度"`。

**问题链**:
1. `"将空调开到27度，两级风速"` 中包含子串 `"开到"`
2. `"开到"` 在 `nav_keywords` 中 → 导航意图被触发
3. 正则 `(开到)([^，。！？?]+)` 匹配到 `"开到27度"` → `destination = "27度"`
4. 返回 `Navigation_Action`，与 `Climate_Action` 合并

**核心矛盾**: `"开到"` 在空调语境中是"设置到（某温度）"的意思，在导航语境中是"驾驶到（某地）"的意思。启发式路由无法区分语境。

#### 修复后代码（当前状态）

文件: `backend_design/nexus/intent/heuristic.py` 第 197-254 行

```python
def _extract_navigation(self, text: str) -> dict[str, Any]:
    # ... 位置查询检查 ...

    # P2 修复: 空调/车控语境排除 — "空调开到27度" 中的 "开到" 是温度设置，不是导航
    # 只有同时包含明确的导航关键词(导航/带我去/前往/去往)才不排除
    climate_keywords = ("空调", "车内温度", "风量", "风速", "制冷", "制热", "除雾", "座椅", "车窗", "车况")
    if any(k in text for k in climate_keywords):
        if not any(k in text for k in ("导航", "带我去", "前往", "去往", "回")):
            return {}

    nav_keywords = (
        "导航", "带我", "前往", "回家", "充电站",
        "去公司", "去学校", "去机场", "开去", "去往",  # ← "开到" 已从此列表移除
    )
    if not any(k in text for k in nav_keywords):
        # "开到" 单独检查 — 仅当后面不是数字(温度)时才视为导航
        if "开到" in text:
            after_kai_dao = text[text.index("开到") + 2:]
            if re.match(r"\d", after_kai_dao):
                return {}  # "开到27度" → 空调语境，不触发导航
        elif not re.search(r"去[^，。！？?]{1,12}(家|公司|学校|机场|医院|商场|车站|充电站)", text):
            return {}

    # ... 提取目的地 ...
```

### P3: 空调风量参数传递异常 — "两级风速"未被解析

> ✅ **已修复** — `heuristic.py` 第 92-107 行已增加多模式风量解析 + 中文数字支持

#### 复现步骤

1. 用户输入: `"将空调开到27度，两级风速"`
2. 日志输出:
   ```
   Sandbox audit: tool=vehicle_climate, status=ok, args={'op': 'set_temp', 'target_temp': 27}
   ```
3. 实际行为: 仅设置了温度 27 度，`fan_speed` 参数丢失
4. 预期行为: 同时设置温度 27 度 + 风量 2 档

#### 根因定位（修复前代码）

文件: `backend_design/nexus/intent/heuristic.py`

修复前风量解析仅有一行正则 `re.search(r"风量(\d+)", text)`，只匹配 `"风量2"` 这种格式。

**问题**:
- 正则 `r"风量(\d+)"` 只匹配 `"风量2"` 这种格式
- 用户说 `"两级风速"` — 使用了 `"风速"` 而非 `"风量"`，且 `"两"` 是中文数字
- 用户说 `"2级风量"` 或 `"风量调到2"` 等表达也无法匹配

#### 修复后代码（当前状态）

文件: `backend_design/nexus/intent/heuristic.py` 第 92-107 行

```python
# 风量解析 — 支持多种表达: "风量2" / "2级风量" / "风速2" / "两级风速" / "2档风速"
fan_speed = None
fan_match = (
    re.search(r"风量(\d+)", text)
    or re.search(r"(\d+)\s*级\s*风[速量]", text)
    or re.search(r"风[速量](\d+)", text)
    or re.search(r"(\d+)\s*档\s*风", text)
    or re.search(r"(\d+)\s*档\s*风速", text)
)
if fan_match:
    fan_speed = int(fan_match.group(1))
else:
    # 中文数字: "两级风速" / "两档风量" 等
    cn_match = re.search(r"([一两二三四五六七八十])\s*[级档]\s*风[速量]", text)
    if cn_match:
        fan_speed = self._CN_NUM_MAP.get(cn_match.group(1))
```

```python
def _extract_window(self, text: str) -> dict[str, Any]:
    if not any(k in text for k in ("车窗", "窗", "天窗")):
        return {}

    if any(k in text for k in ("打开", "升起", "上升", "开窗")):
        op, percent = "open", 100
    elif any(k in text for k in ("关闭", "关上", "落下", "升窗")):
        op, percent = "close", 0
    elif any(k in text for k in ("半开", "开一半", "开一点")):
        op, percent = "set", 50
    else:
        op, percent = "status", None

    # 百分比解析: "开到30%" 等
    percent_match = re.search(r"(?:开到|调到|设为)(\d{1,3})\s*%", text)
    if percent_match and op != "status":
        percent = max(0, min(100, int(percent_match.group(1))))
        op = "set"

    # 位置解析 — 支持单独车窗控制（P4 修复）
    if "天窗" in text:
        position = "sunroof"
    elif any(k in text for k in ("左前", "主驾", "驾驶位", "驾驶员")):
        position = "front_left"
    elif any(k in text for k in ("右前", "副驾", "乘客", "副驾驶")):
        position = "front_right"
    elif any(k in text for k in ("左后", "后排左", "后座左")):
        position = "rear_left"
    elif any(k in text for k in ("右后", "后排右", "后座右")):
        position = "rear_right"
    else:
        position = "all"

    return {"Window_Action": {"op": op, "position": position, "percent": percent}}
```

> ⚠️ **注意**: 上述代码中 `"升起"` 和 `"上升"` 被放在 `open` 分支，`"落下"` 被放在 `close` 分支，这与中文车窗语义存在冲突。详见 [6.5 节](#65-车窗关键词语义反转-升起上升落位置错误)。

### 6.5 车窗关键词语义反转 — "升起"/"上升"/"落下" 放错分支

> 文件: `backend_design/nexus/intent/heuristic.py` 第 134-137 行
> 状态: ⚠️ 未修复

当前 `_extract_window` 方法中，车窗操作判断的关键词存在语义反转问题:

```python
if any(k in text for k in ("打开", "升起", "上升", "开窗")):
    op, percent = "open", 100
elif any(k in text for k in ("关闭", "关上", "落下", "升窗")):
    op, percent = "close", 0
```

**问题分析**:

在中文车窗语境中:
- `"升起"` = 玻璃上升 = **关闭**车窗，但被放在了 `open`（打开）分支 ✗
- `"上升"` = 玻璃上升 = **关闭**车窗，但被放在了 `open`（打开）分支 ✗
- `"落下"` = 玻璃下降 = **打开**车窗，但被放在了 `close`（关闭）分支 ✗
- `"升窗"` = 升起车窗 = **关闭**车窗，正确放在 `close` 分支 ✓

这意味着用户说 `"升起车窗"`（意图关闭）时，系统会执行 `op=open`（打开），意图被反向执行。与 P1（"关闭音乐"→play）属于同类语义反转问题。

**修复建议**:

```python
if any(k in text for k in ("打开", "开窗", "降下", "降窗", "落下")):
    op, percent = "open", 100
elif any(k in text for k in ("关闭", "关上", "升起", "上升", "升窗")):
    op, percent = "close", 0
```

## 七、总结

本次分析从运行日志出发，逐层追踪到源码，共发现 **6 个已确认问题** 和 **5 个潜在问题**。其中 P1（音乐反向执行）和 P2（空调误路由导航）是最严重的用户体验问题，P6（tool_result 覆盖）是最关键的架构缺陷。

**修复进度**: P1-P6 全部已修复，代码中已注入对应注释标记（如 `# P1 修复`、`# P6 修复` 等）。第三优先级的 B3 多专家回复汇总和 Reflection 系统能力注入也已完成。

**全域加固完成** (2026-08-03):

在 P1-P6 修复基础上，进一步完成了全域车载交互加固:

1. **多需求并行调度架构重构**: `vehicle_expert.py` 废弃首个匹配即 return，改为遍历全部 intent 字段，`asyncio.gather` 并行执行 + 互斥组串行
