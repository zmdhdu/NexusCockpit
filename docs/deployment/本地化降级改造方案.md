# NexusCockpit 全私有化本地部署架构降级改造方案（Downgrade Plan）

> **核心目标**：剥离所有云端存储与云端服务依赖，降级为全私有化本地架构，实现数据不出本地硬件环境的全方位隐私管控。
>
> **改造原则**：在项目原有业务功能完全可用的前提下，依靠本地化部署实现全方位的数据隐私管控。
>
> **保留不动**：① 云端工具接口调用逻辑（美团技能 API、Tavily 搜索 API、高德地图 API 等）；② MCP 协议连接逻辑（车控 MCP stdio JSON-RPC 通信）。

## 一、现有项目架构与依赖项详细拆解分析

### 1.1 七层分层架构总览

```
L7  可观测层    →  Langfuse (cloud.langfuse.com) / Prometheus / Grafana / Loki
L6  API 层      →  FastAPI REST / SSE / WebSocket / JWT
L5  中间件层    →  Redis 语义缓存 / 限流 / 会话存储 / 进程内异步任务
L4  Agent 层    →  Supervisor → 5 Expert Agents (并行) → Responder → Reflection → Reviewer
L3  服务层      →  ASR (SenseVoice) / TTS (CosyVoice) / Skills / Vehicle / Intent / MCP
L2  数据层      →  GraphRAG (Milvus + Neo4j + BM25) / Memory / Vector Store / Graph Store
L1  核心层      →  Config / Logger / Exceptions / Circuit Breaker / DB Manager
L0  基础设施层  →  Docker Compose / Milvus / Neo4j / Redis / MySQL / etcd / MinIO
```

### 1.4 云端依赖详细分析

#### 1.4.1 LLM 云端依赖（硅基流动 / 火山方舟）

**调用方式**：通过 `AsyncOpenAI` SDK（OpenAI 兼容协议），共 7 处调用点。

| 调用点 | 文件路径 | 功能 |
|--------|----------|------|
| Supervisor | `nexus/agent/supervisor_graph.py:45` | 意图分派 + 专家调度 |
| Responder | `nexus/agent/responder.py:23` | 最终回复生成 + 流式输出 |
| LLM Intent Router | `nexus/intent/llm_router.py:16` | Function Calling 意图路由 |
| Intent Router | `nexus/intent/router.py` | 意图路由备选路径 |
| Context Compressor | `nexus/memory/compressor.py` | 对话历史压缩摘要 |
| Memory Manager | `nexus/memory/manager.py` | 长期记忆提取 |
| Conflict Resolver | `nexus/memory/conflict.py` | 记忆冲突解决 |

**配置入口**：`config.py` → `LLMConfig`
```python
ark_api_key      # 硅基流动 API Key
ark_base_url     # https://api.siliconflow.cn/v1
llm_model        # deepseek-ai/DeepSeek-V3
```

**已有降级机制**：`LLM_FALLBACK_ENABLED=true` 时，云端不可用自动降级到本地 llama.cpp（Qwen3.5-4B），但当前默认关闭。

#### 1.4.2 Embedding 云端依赖（硅基流动）

**调用方式**：通过 `httpx` 异步 HTTP 调用 `/embeddings` 端点。

| 调用点 | 文件路径 | 功能 |
|--------|----------|------|
| EmbeddingService | `nexus/rag/embedding.py:39-46` | 文本向量化（单条 + 批量） |

**被依赖方**：
- `MilvusVectorStore` — 向量检索前查询向量化
- `SemanticCache` — 语义缓存查询向量化

**配置入口**：`config.py` → `LLMConfig`
```python
embedding_model  # Qwen/Qwen3-Embedding-4B
embedding_dim    # 2560
embedding_url    # {ark_base_url}/embeddings
```

### 3.2 Langfuse 本地化落地建议

#### 3.2.1 为什么需要本地化 Langfuse

当前 Langfuse 配置默认连接 `cloud.langfuse.com`（德国法兰克福 SaaS），所有 LLM 调用链路数据（包含用户对话内容、Prompt、Response）都上传到境外服务器，存在严重的数据隐私风险。

#### 3.2.2 本地化方案

Langfuse 提供官方开源自托管 Docker 镜像，功能与云端 SaaS 完全一致：

```yaml
# docker-compose.yml 新增服务
langfuse-db:
  image: postgres:15-alpine
  environment:
    POSTGRES_USER: langfuse
    POSTGRES_PASSWORD: ${LANGFUSE_DB_PASSWORD:-langfuse}
    POSTGRES_DB: langfuse
  volumes:
    - langfuse_db_data:/var/lib/postgresql/data
  healthcheck:
    test: ["CMD-SHELL", "pg_isready -U langfuse"]
    interval: 10s
    timeout: 5s
    retries: 5

langfuse:
  image: langfuse/langfuse:latest
  ports:
    - "3101:3000"   # 避让 Loki 的 3100 端口
  environment:
    DATABASE_URL: postgresql://langfuse:${LANGFUSE_DB_PASSWORD:-langfuse}@langfuse-db:5432/langfuse
    NEXTAUTH_SECRET: ${LANGFUSE_NEXTAUTH_SECRET:-changeme}
    SALT: ${LANGFUSE_SALT:-changeme}
    NEXTAUTH_URL: http://localhost:3101
    TELEMETRY_ENABLED: "false"     # 禁用遥测上报
    CLICKHOUSE_URL: ""             # 不使用 ClickHouse（小规模不需要）
  depends_on:
    langfuse-db:
      condition: service_healthy
  healthcheck:
    test: ["CMD", "wget", "-q", "--spider", "http://localhost:3000/api/health"]
    interval: 15s
    timeout: 5s
    retries: 5
```

#### 4.3.2 本地 Embedding 实现

```python
# backend_design/nexus/rag/local_embedding.py (新建)
"""
Local Embedding Service — 基于 sentence-transformers 的本地文本向量化服务

使用 BAAI/bge-m3 模型 (1024 维)，完全本地推理，数据不出服务器。
"""

from sentence_transformers import SentenceTransformer
from nexus.config import get_config
from nexus.core.logger import get_logger

logger = get_logger(__name__)

class LocalEmbeddingService:
    """本地 Embedding 服务 (sentence-transformers)"""

    def __init__(self, model_path: str = "./models/embedding/bge-m3"):
        self.config = get_config().llm
        self._model = SentenceTransformer(
            model_path,
            device="cuda" if self._has_gpu() else "cpu",
        )
        self._dim = self._model.get_sentence_embedding_dimension()
        logger.info(f"LocalEmbedding loaded: dim={self._dim}, device={self._model.device}")

    async def embed(self, text: str) -> list[float]:
        if not text or not text.strip():
            return [0.0] * self._dim
        vec = self._model.encode(text, normalize_embeddings=True)
        return vec.tolist()

    async def embed_batch(self, texts: list[str], batch_size: int = 32) -> list[list[float]]:
        if not texts:
            return []
        vecs = self._model.encode(
            texts, batch_size=batch_size,
            normalize_embeddings=True,
            show_progress_bar=False,
        )
        return [v.tolist() for v in vecs]

    @staticmethod
    def _has_gpu() -> bool:
        try:
            import torch
            return torch.cuda.is_available()
        except ImportError:
            return False

    async def close(self) -> None:
        pass  # sentence-transformers 无需显式关闭
```

#### 4.3.3 Embedding 工厂模式

```python
# backend_design/nexus/rag/embedding_factory.py (新建)
"""
Embedding Factory — 向量化服务工厂

根据 EMBEDDING_PROVIDER 配置选择后端:
  - local: 本地 sentence-transformers (bge-m3)
  - cloud: 云端 API (硅基流动/火山方舟)
"""

from nexus.config import get_config
from nexus.core.logger import get_logger
from nexus.rag.embedding import EmbeddingService

logger = get_logger(__name__)

def build_embedding_service():
    """根据配置选择 Embedding 服务后端"""
    provider = getattr(get_config().llm, "embedding_provider", "cloud")

    if provider == "local":
        from nexus.rag.local_embedding import LocalEmbeddingService
        logger.info("Embedding provider: local bge-m3")
        return LocalEmbeddingService()
    else:
        logger.info("Embedding provider: cloud API")
        return EmbeddingService()
```

#### 7.1.2 语义缓存代码对 RediSearch 的依赖

`nexus/middleware/redis_cache.py` 中 `SemanticCache` 类的核心逻辑：

```python
# 索引创建 — 依赖 RediSearch 模块
await self._redis.ft(_INDEX_NAME).create_index(schema, definition=definition)

# KNN 向量检索 — 依赖 RediSearch VECTOR 字段类型
Query(f"{filter_expr} =>[KNN 1 @embedding $vec AS score]")

# 降级模式 — 无 RediSearch 时走 O(n) scan
if cache_provider == "cloud":
    self._index_ready = False  # 跳过 VECTOR 索引
```

**关键发现**：代码已实现双模式兼容（RediSearch KNN / Scan 降级），但本地化改造后必须确保 RediSearch 模块可用，否则语义缓存退化为 O(n) 遍历，数据量增长后性能急剧下降。

#### 7.1.3 本地裸 Redis（非 Stack）场景

如果开发者本地安装的是普通 Redis（如 `redis:7.2` 而非 `redis-stack-server`），则：

| 功能 | 普通 Redis | Redis Stack |
|------|-----------|-------------|
| 基本缓存（GET/SET/HSET） | ✅ 可用 | ✅ 可用 |
| 会话存储（SessionStore） | ✅ 可用 | ✅ 可用 |
| 限流计数器 | ✅ 可用 | ✅ 可用 |
| 语义缓存 KNN 检索 | ❌ 不可用 | ✅ 可用 |
| 语义缓存 Scan 降级 | ✅ 可用（O(n)） | ✅ 可用（O(log n)） |
| 多座舱 DB 分区 | ✅ 可用 | ✅ 可用 |

## 八、llama.cpp 子进程集成方案（进程内嵌入而非独立 Docker 服务）

### 8.1 当前状态分析

#### 8.1.1 现有降级机制

`config.py` 中已有本地 LLM 降级配置：

```python
# 本地 LLM 降级配置（llama.cpp OpenAI 兼容接口）
fallback_enabled: bool = Field(default=False)
fallback_base_url: str = Field(default="http://127.0.0.1:8082/v1")  # llama.cpp 默认地址
fallback_model: str = Field(default="qwen3.5-4b-local")
fallback_api_key: str = Field(default="")
fallback_timeout: float = Field(default=60.0)
```

**问题**：当前方案需要用户**手动启动** llama.cpp server（`./llama-server --model xxx.gguf --port 8082`），然后通过 HTTP 调用。这不是真正的"子进程集成"，存在以下痛点：

| 痛点 | 描述 |
|------|------|
| 需手动启动 | 用户忘记启动 llama.cpp server 时，降级链路断裂 |
| 生命周期脱节 | Python 服务停止后 llama.cpp 进程仍在运行，造成资源泄漏 |
| 无健康检查 | llama.cpp server 崩溃后无法自动恢复 |
| 端口冲突 | 手动管理端口，多实例场景混乱 |

#### 8.1.2 目标方案

将 llama.cpp 作为 Python 服务的**子进程**管理，由 Python 进程统一编排生命周期：

```
Python 主进程 (uvicorn)
  ├── FastAPI 应用
  ├── LlamaCppProcessManager (子进程管理器)
  │     └── llama-server 子进程 (GGUF 模型推理)
  └── 其他异步任务
```

#### 8.2.2 核心实现

```python
# backend_design/nexus/core/llama_cpp_manager.py (新建)

"""
LlamaCpp Process Manager — llama.cpp 子进程生命周期管理

将 llama-server 作为 Python 服务的子进程运行，实现:
  - 启动时自动拉起 llama-server
  - 健康检查 + 崩溃自动重启
  - 优雅停止（SIGTERM → 等待 → SIGKILL）
  - GPU/CPU 自动检测与参数选择
  - 模型热切换（reload）

依赖: 需预编译 llama.cpp 或下载预编译二进制
  - Windows: llama-server.exe
  - Linux: llama-server
  - 路径: ./bin/llama-server (或通过 .env 配置)
"""

from __future__ import annotations

import asyncio
import os
import signal
import subprocess
import sys
from typing import Any

import httpx

from nexus.config import get_config
from nexus.core.logger import get_logger

logger = get_logger(__name__)


class LlamaCppProcessManager:
    """llama.cpp 子进程管理器。

    在 Python 服务启动时自动拉起 llama-server 子进程，
    提供健康检查、崩溃重启、优雅停止等生命周期管理。

    Attributes:
        _process: 子进程 Popen 对象
        _port: llama-server 监听端口
        _binary_path: llama-server 二进制路径
        _model_path: GGUF 模型文件路径
        _max_restarts: 最大重启次数
        _restart_count: 当前重启计数
        _health_check_url: 健康检查 URL
        _shutdown_event: 停止信号
    """

    def __init__(self):
        config = get_config().llm
        self._binary_path = os.getenv(
            "LLAMA_CPP_BINARY",
            self._default_binary_path(),
        )
        self._model_path = os.getenv(
            "LLAMA_CPP_MODEL_PATH",
            os.path.join(
                os.path.dirname(os.path.dirname(os.path.dirname(
                    os.path.dirname(os.path.abspath(__file__))
                ))),
                "models", "llm", "qwen2.5-7b-instruct-q4_k_m.gguf"
            ),
        )
        self._port = int(os.getenv("LLAMA_CPP_PORT", "8082"))
        self._host = "127.0.0.1"
        self._ctx_size = int(os.getenv("LLAMA_CPP_CTX_SIZE", "4096"))
        self._gpu_layers = int(os.getenv("LLAMA_CPP_GPU_LAYERS", "0"))
        self._threads = int(os.getenv("LLAMA_CPP_THREADS", str(os.cpu_count() or 4)))
        self._max_restarts = 3
        self._restart_count = 0
        self._process: subprocess.Popen | None = None
        self._health_check_url = f"http://{self._host}:{self._port}/health"
        self._shutdown_event = asyncio.Event()

    @staticmethod
    def _default_binary_path() -> str:
        """根据操作系统返回默认二进制路径。"""
        project_root = os.path.dirname(os.path.dirname(os.path.dirname(
            os.path.dirname(os.path.abspath(__file__))
        )))
        if sys.platform == "win32":
            return os.path.join(project_root, "bin", "llama-server.exe")
        return os.path.join(project_root, "bin", "llama-server")

    async def start(self) -> bool:
        """启动 llama-server 子进程。

        Returns:
            True 表示启动成功且健康检查通过
        """
        if not os.path.exists(self._binary_path):
            logger.warning(
                f"llama-server binary not found at {self._binary_path}, "
                f"subprocess integration disabled"
            )
            return False

        if not os.path.exists(self._model_path):
            logger.warning(
                f"GGUF model not found at {self._model_path}, "
                f"subprocess integration disabled"
            )
            return False

        logger.info(
            f"Starting llama-server: binary={self._binary_path}, "
            f"model={self._model_path}, port={self._port}, "
            f"ctx={self._ctx_size}, gpu_layers={self._gpu_layers}, "
            f"threads={self._threads}"
        )

        cmd = [
            self._binary_path,
            "--model", self._model_path,
            "--host", self._host,
            "--port", str(self._port),
            "--ctx-size", str(self._ctx_size),
            "--threads", str(self._threads),
            "--gpu-layers", str(self._gpu_layers),
            "--parallel", "4",           # 支持多专家并行请求
            "--cont-batching",           # 连续批处理
            "--metrics",                 # 启用 Prometheus 指标
        ]

        try:
            self._process = subprocess.Popen(
                cmd,
                stdout=subprocess.PIPE,
                stderr=subprocess.STDOUT,
                creationflags=subprocess.CREATE_NO_WINDOW if sys.platform == "win32" else 0,
            )
            logger.info(f"llama-server started (PID={self._process.pid})")

            # 等待健康检查通过（最多 60 秒）
            if await self._wait_for_health(timeout=60):
                logger.info("llama-server healthy, ready to serve")
                self._restart_count = 0
                # 启动后台监控任务
                asyncio.create_task(self._monitor())
                return True
            else:
                logger.error("llama-server failed health check within 60s")
                await self.stop()
                return False

        except Exception as e:
            logger.error(f"Failed to start llama-server: {e}")
            return False

    async def _wait_for_health(self, timeout: float = 60.0) -> bool:
        """等待 llama-server 健康检查通过。"""
        async with httpx.AsyncClient() as client:
            for _ in range(int(timeout / 2)):
                try:
                    resp = await client.get(self._health_check_url, timeout=2.0)
                    if resp.status_code == 200:
                        return True
                except Exception:
                    pass
                await asyncio.sleep(2)
        return False

    async def _monitor(self) -> None:
        """后台监控子进程状态，崩溃时自动重启。"""
        while not self._shutdown_event.is_set():
            if self._process and self._process.poll() is not None:
                # 子进程已退出
                exit_code = self._process.returncode
                logger.error(f"llama-server exited (code={exit_code})")

                if self._restart_count < self._max_restarts:
                    self._restart_count += 1
                    logger.info(
                        f"Restarting llama-server "
                        f"(attempt {self._restart_count}/{self._max_restarts})"
                    )
                    await asyncio.sleep(3)  # 等待 3 秒后重启
                    await self.start()
                else:
                    logger.error(
                        "llama-server max restart attempts reached, "
                        "falling back to cloud LLM if available"
                    )
                    break

            await asyncio.sleep(5)  # 每 5 秒检查一次

    async def stop(self) -> None:
        """优雅停止 llama-server 子进程。"""
        self._shutdown_event.set()

        if not self._process:
            return

        logger.info("Stopping llama-server...")

        # 先尝试 SIGTERM
        try:
            if sys.platform == "win32":
                self._process.terminate()
            else:
                self._process.send_signal(signal.SIGTERM)

            # 等待最多 10 秒
            try:
                self._process.wait(timeout=10)
            except subprocess.TimeoutExpired:
                # SIGTERM 超时，强制 SIGKILL
                logger.warning("llama-server did not stop gracefully, force killing")
                self._process.kill()
                self._process.wait(timeout=5)

            logger.info("llama-server stopped")
        except Exception as e:
            logger.error(f"Error stopping llama-server: {e}")
            if self._process:
                self._process.kill()
        finally:
            self._process = None

    @property
    def is_running(self) -> bool:
        """子进程是否正在运行。"""
        return self._process is not None and self._process.poll() is None

    @property
    def base_url(self) -> str:
        """OpenAI 兼容 API 的 base URL。"""
        return f"http://{self._host}:{self._port}/v1"
```

### 9.2 私有化 Embedding 模型选型矩阵

| 模型 | 维度 | 模型大小 | 多语言 | 推理引擎 | GPU 需求 | 推荐度 |
|------|------|----------|--------|----------|----------|--------|
| **BAAI/bge-m3** | 1024 | ~2.2GB | ✅ 中英日韩 | sentence-transformers | 可选 | ⭐⭐⭐⭐⭐ |
| BAAI/bge-large-zh-v1.5 | 1024 | ~1.3GB | 中文优先 | sentence-transformers | 可选 | ⭐⭐⭐⭐ |
| BAAI/bge-small-zh-v1.5 | 512 | ~130MB | 中文优先 | sentence-transformers | 不需要 | ⭐⭐⭐ |
| jinaai/jina-embeddings-v3 | 1024 | ~2.3GB | ✅ 89 语言 | sentence-transformers | 可选 | ⭐⭐⭐⭐ |
| Qwen/Qwen3-Embedding-4B | 2560 | ~8GB | ✅ 多语言 | vLLM / transformers | 推荐 GPU | ⭐⭐⭐ |

**推荐方案：BAAI/bge-m3 + sentence-transformers**，理由：

1. **与 Reranker 技术栈统一**：项目已使用 `bge-reranker-v2-m3`（BAAI 系列），Embedding 同样选用 BGE 系列，技术栈一致性高
2. **sentence-transformers 已安装**：`requirements.txt` 中已有 `sentence-transformers>=2.7.0`，无需新增依赖
3. **CPU/GPU 自适应**：无 GPU 时纯 CPU 推理，单条文本延迟 ~50ms（CPU），~5ms（GPU）
4. **维度兼容性**：1024 维，比当前 2560 维节省 60% 存储空间，Milvus 检索更快
5. **多语言支持**：bge-m3 原生支持中英日韩等 100+ 语言，适合车载多语言场景

```python
# backend_design/nexus/rag/local_embedding.py (新建)

"""
Local Embedding Service — 基于 sentence-transformers 的本地文本向量化服务

使用 BAAI/bge-m3 模型 (1024 维)，完全本地推理，数据不出服务器。
与 LocalReranker (bge-reranker-v2-m3) 同属 BAAI BGE 系列，技术栈统一。

模型路径: ./models/embedding/bge-m3/
依赖: sentence-transformers>=2.7.0 (已安装)
"""

from __future__ import annotations

import asyncio
import os
from typing import Any

from nexus.core.logger import get_logger

logger = get_logger(__name__)

_DEFAULT_MODEL_PATH = os.path.join(
    os.path.dirname(os.path.dirname(os.path.dirname(
        os.path.dirname(os.path.abspath(__file__))
    ))),
    "models", "embedding", "bge-m3"
)


class LocalEmbeddingService:
    """本地 Embedding 服务 (sentence-transformers + bge-m3)。

    与 EmbeddingService (云端 Ark API) 接口完全一致，可无缝替换。
    支持 CPU/GPU 自动切换，批量向量化。

    Attributes:
        _model: SentenceTransformer 模型实例
        _dim: 输出向量维度
        _loaded: 是否已加载
    """

    def __init__(self, model_path: str = ""):
        self.model_path = model_path or _DEFAULT_MODEL_PATH
        self._model = None
        self._dim = 1024  # bge-m3 默认维度
        self._loaded = False
        self._load_error = ""

    def _ensure_loaded(self) -> bool:
        """延迟加载模型（首次调用时加载）。"""
        if self._loaded:
            return True
        if self._model is not None:
            return True

        if not os.path.exists(self.model_path):
            self._load_error = f"Model not found at {self.model_path}"
            logger.warning(self._load_error)
            return False

        try:
            from sentence_transformers import SentenceTransformer

            # GPU/CPU 自动检测
            device = self._detect_device()

            self._model = SentenceTransformer(
                self.model_path,
                device=device,
            )
            self._dim = self._model.get_sentence_embedding_dimension()
            self._loaded = True
            logger.info(
                f"LocalEmbedding loaded: model=bge-m3, "
                f"dim={self._dim}, device={device}"
            )
            return True

        except ImportError:
            self._load_error = "sentence-transformers not installed"
            logger.warning(self._load_error)
            return False
        except Exception as e:
            self._load_error = str(e)
            logger.error(f"Failed to load embedding model: {e}")
            return False

    @staticmethod
    def _detect_device() -> str:
        """检测可用计算设备。"""
        try:
            import torch
            if torch.cuda.is_available():
                return "cuda"
            # Apple Silicon
            if hasattr(torch.backends, "mps") and torch.backends.mps.is_available():
                return "mps"
        except ImportError:
            pass
        return "cpu"

    async def embed(self, text: str) -> list[float]:
        """获取单条文本的 embedding 向量。

        Args:
            text: 待向量化的文本

        Returns:
            1024 维浮点列表，空文本返回零向量
        """
        if not text or not text.strip():
            return [0.0] * self._dim

        if not self._ensure_loaded():
            logger.error(f"Embedding model not loaded: {self._load_error}")
            return [0.0] * self._dim

        # sentence-transformers 的 encode 是同步方法，
        # 使用 run_in_executor 避免阻塞事件循环
        loop = asyncio.get_event_loop()
        vec = await loop.run_in_executor(
            None,
            lambda: self._model.encode(
                text,
                normalize_embeddings=True,
            )
        )
        return vec.tolist()

    async def embed_batch(
        self, texts: list[str], batch_size: int = 32
    ) -> list[list[float]]:
        """批量获取 embedding。

        Args:
            texts: 文本列表
            batch_size: 每批最大文本数

        Returns:
            向量列表，顺序与输入一致
        """
        if not texts:
            return []

        if not self._ensure_loaded():
            return [[0.0] * self._dim] * len(texts)

        loop = asyncio.get_event_loop()
        vecs = await loop.run_in_executor(
            None,
            lambda: self._model.encode(
                texts,
                batch_size=batch_size,
                normalize_embeddings=True,
                show_progress_bar=False,
            )
        )
        return [v.tolist() for v in vecs]

    @property
    def dimension(self) -> int:
        """返回当前模型的向量维度。"""
        return self._dim

    @property
    def is_available(self) -> bool:
        """模型是否已加载可用。"""
        return self._loaded

    async def close(self) -> None:
        """释放模型资源。"""
        if self._model is not None:
            # sentence-transformers 内部使用 PyTorch，无需显式释放
            self._model = None
            self._loaded = False
```

# backend_design/nexus/agent/llm_client_factory.py (新建)

"""
LLM Client Factory — 统一 LLM 客户端创建

解决 7 处独立创建 AsyncOpenAI 的问题：
  - 连接池复用
  - 统一降级逻辑
  - 配置集中管理
"""

from __future__ import annotations

from openai import AsyncOpenAI

from nexus.config import get_config
from nexus.core.logger import get_logger

logger = get_logger(__name__)

# 全局单例缓存
_primary_client: AsyncOpenAI | None = None
_fallback_client: AsyncOpenAI | None = None


def get_llm_client() -> AsyncOpenAI:
    """获取主 LLM 客户端（单例）。

    根据 .env 配置自动选择:
      - 云端: 硅基流动 / 火山方舟
      - 本地: vLLM / llama.cpp (通过 ARK_BASE_URL 指向本地)
    """
    global _primary_client
    if _primary_client is not None:
        return _primary_client

    config = get_config().llm
    _primary_client = AsyncOpenAI(
        api_key=config.ark_api_key or "not-needed",
        base_url=config.ark_base_url,
        timeout=config.timeout,
    )
    logger.info(f"LLM client created: base_url={config.ark_base_url}")
    return _primary_client


def get_fallback_llm_client() -> AsyncOpenAI | None:
    """获取降级 LLM 客户端（单例）。

    当 LLM_FALLBACK_ENABLED=true 时返回降级客户端，否则返回 None。
    """
    global _fallback_client
    if _fallback_client is not None:
        return _fallback_client

    config = get_config().llm
    if not config.fallback_enabled:
        return None

    _fallback_client = AsyncOpenAI(
        api_key=config.fallback_api_key or "not-needed",
        base_url=config.fallback_base_url,
        timeout=config.fallback_timeout,
    )
    logger.info(f"Fallback LLM client created: base_url={config.fallback_base_url}")
    return _fallback_client


async def call_llm_with_fallback(
    messages: list[dict],
    model: str | None = None,
    temperature: float = 0.7,
    max_tokens: int = 512,
    **kwargs,
) -> str:
    """带降级的 LLM 调用。

    优先使用主 LLM，失败时自动降级到 fallback LLM。

    Returns:
        LLM 生成的文本
    """
    config = get_config().llm
    primary_model = model or config.llm_model

    try:
        client = get_llm_client()
        response = await client.chat.completions.create(
            model=primary_model,
            messages=messages,
            temperature=temperature,
            max_tokens=max_tokens,
            **kwargs,
        )
        return response.choices[0].message.content or ""
    except Exception as e:
        logger.warning(f"Primary LLM failed: {e}")

        fallback = get_fallback_llm_client()
        if fallback is None:
            raise

        logger.info("Falling back to local LLM")
        response = await fallback.chat.completions.create(
            model=config.fallback_model,
            messages=messages,
            temperature=temperature,
            max_tokens=max_tokens,
            **kwargs,
        )
        return response.choices[0].message.content or ""
```

    DispatchNode,

    ReviewerNode,
    SupervisorNode,

from nexus.skills.registry import SkillRegistry

logger = get_logger(__name__)


class SupervisorGraph:
    """Multi-Agent 工作流编排器（瘦身版）。"""

    def __init__(
        self,
        intent_router: IntentRouterService,
        memory_manager: MemoryManager,
        skill_registry: SkillRegistry,
        llm_client=None,
        checkpoint_saver=None,
    ):
        self.llm_client = llm_client or get_llm_client()

        # 组装组件
        responder = ResponderAgent(self.llm_client)
        reviewer = ReviewerAgent(memory_manager)

        # 组装节点
        self.supervisor = SupervisorNode(
            intent_router, memory_manager, skill_registry, responder
        )
        self.dispatcher = DispatchNode()
        self.responder_node = ResponderNode(responder, self.llm_client)
        self.reflection_node = ReflectionNode(self.llm_client)
        self.reviewer_node = ReviewerNode(reviewer)

        # 构建图
        self._graph = GraphBuilder(
            supervisor=self.supervisor,
            dispatcher=self.dispatcher,
            responder=self.responder_node,
            reflection=self.reflection_node,
            reviewer=self.reviewer_node,
        ).build(checkpoint_saver)

    async def invoke(self, state: SupervisorState) -> SupervisorState:
        """同步执行工作流。"""
        result = await self._graph.ainvoke(state)
        return result

    async def stream(self, state: SupervisorState):
        """流式执行工作流。"""
        async for chunk in self._graph.astream(state):
            yield chunk

# 简易替代方案 — 不依赖 langchain
class SimpleRecursiveTextSplitter:
    """递归字符文本分割器（langchain-text-splitters 简化版）。"""

    def __init__(self, chunk_size=500, chunk_overlap=50, separators=None):
        self.chunk_size = chunk_size
        self.chunk_overlap = chunk_overlap
        self.separators = separators or ["\n\n", "\n", "。", "！", "？", "；", "，", " ", ""]

    def split_text(self, text: str) -> list[str]:
        """递归分割文本。"""
        if len(text) <= self.chunk_size:
            return [text] if text.strip() else []

        for sep in self.separators:
            if sep in text:
                parts = text.split(sep)
                chunks = []
                current = ""
                for part in parts:
                    candidate = current + sep + part if current else part
                    if len(candidate) <= self.chunk_size:
                        current = candidate
                    else:
                        if current:
                            chunks.append(current)
                        current = part
                if current:
                    chunks.append(current)
                return chunks

        # 最后 fallback: 按字符长度硬切
        return [text[i:i+self.chunk_size] for i in range(0, len(text), self.chunk_size - self.chunk_overlap)]
```

### 11.2 问题详细分析

#### 11.2.1 SQLite Checkpoint 单机瓶颈

**现状**：`nexus/main.py` 使用 `AsyncSqliteSaver` 持久化 LangGraph checkpoint：

```python
from langgraph.checkpoint.sqlite.aio import AsyncSqliteSaver
db_path = os.path.join(os.getcwd(), "data", "checkpoints", "nexus_checkpoints.db")
```

**问题**：
- SQLite 单文件写入，多座舱高并发时可能出现 `database is locked` 错误
- 无法跨节点共享 checkpoint（多实例部署时问题）
- 文件锁竞争导致延迟抖动

**建议**：
- P4 阶段评估迁移到 PostgreSQL checkpoint（`langgraph-checkpoint-postgres`）
- 或使用 Redis 作为 checkpoint 后端（`langgraph-checkpoint-redis`）
- 短期方案：启用 SQLite WAL 模式 + 增大 `busy_timeout`

#### 11.2.2 ASR/TTS 模型加载阻塞启动

**现状**：`nexus/asr/engine.py` 中 SenseVoice 模型在应用启动时同步加载：

```python
class ASREngine:
    def __init__(self):
        self._model = None
        self._loaded = False
        # 首次调用 transcribe() 时才加载（延迟加载）
```

**问题**：
- 虽然是延迟加载，但首次 ASR 请求会阻塞 ~3-5 秒（模型加载时间）
- TTS 模型（CosyVoice ~3.5GB）首次调用时加载更久
- 多个模型同时加载时内存峰值过高

**建议**：
- 在 FastAPI lifespan 中后台预加载模型（`asyncio.create_task`）
- ASR/TTS 分别使用独立线程池加载，不阻塞主事件循环
- 增加加载进度 API，前端可显示"语音引擎加载中"

#### 11.2.3 前端 SSE 长连接无心跳保活

**现状**：前端通过 SSE（Server-Sent Events）接收流式回复，但无心跳机制。

**问题**：
- 网络中间件（Nginx/防火墙）可能在 60-120 秒无数据后断开连接
- 用户长时间思考后发送消息时，SSE 连接可能已失效
- Go 网关的 WebSocket 有 ping/pong，但 Python 后端的 SSE 没有

**建议**：
- 在 SSE 流中每 15 秒发送 `: heartbeat\n\n` 注释行（SSE 规范允许注释）
- 前端增加连接断开自动重连逻辑
- Go 网关配置 `proxy_read_timeout 300s`

#### 11.2.4 知识库文档导入无增量更新

**现状**：`nexus/rag/cherry_kb.py` 的 `CherryKnowledgeBase` 支持文档入库，但无增量更新：

```python
async def add_document(self, text: str, source: str, category: str):
    # 每次 add 都是全新插入，不检查是否已存在
```

**问题**：
- 同一文档修改后重新导入，会产生重复向量（旧分块 + 新分块共存）
- 无法按 source 删除旧文档
- 知识库膨胀后检索质量下降

**建议**：
- 新增 `delete_by_source(source: str)` 方法，按来源删除旧向量
- `add_document` 前自动调用 `delete_by_source` 实现幂等更新
- 记录文档 hash，相同 hash 跳过重新向量化

#### 11.2.5 测试覆盖率不足

**现状**：项目缺乏系统性的单元测试和集成测试。

**建议阶段 P4 任务**：
- 核心模块单元测试覆盖率 ≥ 80%（config / factory / intent_router / memory）
- API 集成测试（FastAPI TestClient）
- Agent 工作流端到端测试（mock LLM）
- CI 流水线增加 `pytest --cov` 门槛

#### 11.2.6 Docker 镜像体积过大

**现状**：Python 后端 Docker 镜像因 PyTorch + modelscope + funasr 等依赖，镜像体积可达 8-10GB。

**建议**：
- 使用多阶段构建（multi-stage build）
- 基础镜像从 `python:3.10` 改为 `python:3.10-slim`
- PyTorch 使用 CPU-only 版本（`--index-url https://download.pytorch.org/whl/cpu`）
- 模型文件不打包进镜像，通过 volume 挂载
- 预计镜像体积可降至 ~2GB

#### 11.2.7 配置热更新缺失

**现状**：配置通过 `get_config()` 全局单例读取，`@lru_cache` 缓存后无法运行时修改。

**建议**：
- 增加配置热更新 API（`POST /admin/config/reload`）
- 关键配置项（temperature, max_tokens, reflection_enabled）支持运行时调整
- 使用 watchdog 监听 `.env` 文件变化自动 reload

#### 11.2.8 [已修复] langfuse.py 缺少 observe / update_current_span 导出

**问题现象**：后端启动时报错 `Agent graph initialization failed: cannot import name 'observe' from 'nexus.observability.langfuse'`，导致整个 Agent 工作流无法初始化。

**根因分析**：

`supervisor_graph.py` 第 63 行导入了两个函数：
```python
from nexus.observability.langfuse import observe, update_current_span
```

但项目自定义的 `nexus/observability/langfuse.py` 包装文件中**只定义了** `LangfuseMonitor` 类和 `NullTrace/NullSpan/NullGeneration` 降级类，**没有导出** `observe` 装饰器和 `update_current_span` 函数。

项目使用 `langfuse==4.5.0`（v4 SDK），这两个函数在 langfuse 包中原生存在，但由于项目自定义文件 `langfuse.py` 与 langfuse 包同名，Python 导入时优先加载项目文件，导致包级函数被遮蔽。

**修复方案**：

在 `nexus/observability/langfuse.py` 中新增 `observe` 装饰器和 `update_current_span` 函数：

1. 尝试从 langfuse 包导入真实实现（`_langfuse_observe` / `_langfuse_update_current_span`）
2. 当 Langfuse SDK 可用且 `config.enabled=true` 时，委托给真实装饰器
3. 当 Langfuse 未安装或未配置时，降级为透传装饰器（函数正常执行但不追踪）

**修改文件**：`backend_design/nexus/observability/langfuse.py`

**验证**：`python -c "from nexus.observability.langfuse import observe, update_current_span; print('OK')"` → 输出 `OK`

#### 11.2.9 [已修复] Redis 非 Stack 版无 RediSearch 模块，语义缓存降级

**问题现象**：后端启动日志输出：
```
Failed to create RediSearch index: unknown command 'FT.CREATE', with args beginning with: ...
Redis Stack semantic cache connected (VECTOR index)
```

第二条日志具有**误导性** —— 索引创建实际已失败，但 `connect()` 方法仍打印 "connected (VECTOR index)" 成功信息。

**根因分析**：

1. 用户的 Redis 实例**缺少 RediSearch 模块**（可能是裸 `redis:7.2` 镜像而非 `redis-stack-server`），`FT.CREATE` 命令不可用
2. `_ensure_index()` 方法内部捕获异常后设置 `_index_ready=False`，但**不 re-raise**，导致 `connect()` 继续执行成功日志
3. 原有代码通过 `cache_provider == "cloud"` 判断是否跳过 RediSearch，这是 provider 级别的判断，**无法检测实际模块是否可用**

**修复方案**：

1. 新增 `_check_redisearch_module()` 方法：通过 `redis.module_list()` 检查 RediSearch 模块是否加载
2. `connect()` 方法改为：先检查模块 → 再创建索引 → 根据 `_index_ready` 实际状态打印正确日志
3. 模块不存在时输出明确的 warning 日志，提示用户使用 `redis/redis-stack-server` 镜像
4. 移除了基于 `cache_provider == "cloud"` 的旧判断逻辑（本地化改造后不再有 cloud 模式）

**修改文件**：`backend_design/nexus/middleware/redis_cache.py`
