## 一、配置文件结构

项目仅需 **2 份后端 env 文件**：

| 文件 | 用途 | 是否提交 GitHub | 说明 |
|------|------|:---:|------|
| `.env` | 统一默认配置 | ✅ 是 | 开箱即用，含所有默认值，开发者克隆即可运行 |
| `.env.local` | 本机覆盖配置 | ❌ 否 | 覆盖 `.env` 中的值，含个人 API Key、调试开关等 |

前端另有 2 份文件（独立管理）：

| 文件 | 用途 | 是否提交 GitHub |
|------|------|:---:|
| `frontend_design/.env.local` | 前端开发配置 | ❌ 否 |
| `frontend_design/.env.local.example` | 前端模板 | ✅ 是 |

### 配置加载逻辑

**Python 后端 (`config.py`):**
```
.env.local 存在 → 加载 .env.local (覆盖 .env 默认值)
.env.local 不存在 → 加载 .env (开箱即用)
```

**Go 网关 (`main.go`):**
```
--env /path/to/file → 加载指定文件
.env.local 存在 → 加载 .env.local
.env 存在 → 加载 .env
未找到 → 使用代码默认值
```

### 快速开始

```bash
# 1. 克隆项目
git clone https://github.com/zmdhdu/NexusCockpit.git
cd NexusCockpit

# 2. 启动中间件 (使用 .env 中的默认值, 无需修改任何配置)
docker compose up -d

# 3. 启动后端 (自动加载 .env)
cd backend_design && python -m nexus.main

# 4. 如需覆盖默认值, 复制 .env.local 并修改
cp .env .env.local
vim .env.local  # 修改你需要的值
```

## 三、`.env` 与 `.env.local` 的关系

```
.env (提交 GitHub, 默认值)
  ├── 开发者克隆 → 直接使用, 无需修改
  └── 你自己的机器 → 复制为 .env.local, 覆盖需要修改的值

.env.local (不提交, 个人覆盖)
  ├── 只写需要覆盖的参数 (未写的参数自动使用 .env 默认值)
  ├── 例如: DEBUG=true, LOG_LEVEL=DEBUG, RBAC_DEFAULT_ROLE=super_admin
  └── 例如: 换成你自己的 ARK_API_KEY
```

### `.env.local` 最小覆盖示例

如果你只需要开启 DEBUG 和切换 RBAC 角色，`.env.local` 只需要写：

```bash
# 覆盖 .env 中的默认值 (其他参数自动继承 .env)
DEBUG=true
LOG_LEVEL=DEBUG
RBAC_DEFAULT_ROLE=super_admin
CORS_ORIGINS=*
COCKPIT_COUNT=3
```

## 四、生产环境密码修改指南

> 当前项目为开源项目，默认值可直接使用。
> 如需部署到生产环境，请在 `.env.local` 中覆盖以下参数。

### 生成强随机密钥

```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"
# 或
openssl rand -base64 32
```

### 必须修改的参数

| 序号 | 参数名 | 当前默认值 | 建议改为 |
|:---:|------|------|------|
| 1 | `NEO4J_PASSWORD` | `nexuscockpit` | 强随机密码 (16+ 字符) |
| 2 | `REDIS_PASSWORD` | `redis_secure_password_2026` | 强随机密码 (16+ 字符) |
| 3 | `MYSQL_PASSWORD` | `nexuscockpit` | 强随机密码 (16+ 字符) |
| 4 | `JWT_SECRET_KEY` | `nexuscockpit_secret_key_2026` | `secrets.token_urlsafe(32)` 生成值 |
| 5 | `RBAC_ADMIN_PASSWORD` | `admin123` | 强随机密码 (16+ 字符) |
| 6 | `RBAC_USER_PASSWORD` | `cockpit_user_2026` | 强随机密码 (16+ 字符) |
| 7 | `MINIO_ACCESS_KEY` | `minioadmin` | 自定义访问密钥 |
| 8 | `MINIO_SECRET_KEY` | `minioadmin` | 强随机密钥 (32+ 字符) |
| 9 | `GRAFANA_ADMIN_PASSWORD` | `admin` | 强随机密码 |
| 10 | `LANGFUSE_DB_PASSWORD` | `langfuse` | 强随机密码 |
| 11 | `LANGFUSE_NEXTAUTH_SECRET` | `changeme-langfuse-secret` | `secrets.token_urlsafe(32)` 生成值 |
| 12 | `LANGFUSE_SALT` | `changeme-langfuse-salt` | `secrets.token_urlsafe(32)` 生成值 |
| 13 | `CORS_ORIGINS` | `http://localhost:3000` | 生产域名 (如 `https://cockpit.example.com`) |
| 14 | `ARK_API_KEY` | (开源公开 Key) | 生产环境独立 API Key |

### 安全检查机制

项目内置生产环境安全检查（设置 `APP_ENV=prod` 时触发）：

**Python 后端 (`config.py`):**
- `JWT_SECRET_KEY` 为空或弱密钥 → **拒绝启动**
- `CORS_ORIGINS` 为 `*` → **拒绝启动**
- `MYSQL_PASSWORD` / `NEO4J_PASSWORD` 为默认值 → 输出警告

**Go 网关 (`config.go`):**
- `JWT_SECRET` 为空或弱密钥 → **拒绝启动**
- `RBAC_ADMIN_PASSWORD` 为 `admin123` → **拒绝启动**
- `CORS_ORIGINS` 为 `*` → **拒绝启动**
- `RBAC_USER_PASSWORD` 未设置 → **拒绝启动**

## 六、修改密码的快速步骤

### 场景 1：修改本机密码

```bash
# 编辑 .env.local, 添加需要覆盖的参数
vim .env.local

# 例如修改 Neo4j 密码
NEO4J_PASSWORD=my_new_password

# 重启服务
docker compose down
docker compose up -d
```

### 场景 2：修改 Docker 中间件密码

```bash
# 在 .env.local 中添加 (覆盖 .env 默认值)
MINIO_ACCESS_KEY=my_access_key
MINIO_SECRET_KEY=my_secret_key_32_chars_long
GRAFANA_ADMIN_PASSWORD=my_grafana_password

# 重启后生效
docker compose down
docker compose up -d
```

### 场景 3：部署到生产环境

```bash
# 1. 创建 .env.local 覆盖生产值
cp .env .env.local
vim .env.local  # 修改所有密码为强随机值

# 2. 设置生产环境标识
# 在 .env.local 中添加:
APP_ENV=prod
DEBUG=false
LOG_LEVEL=WARNING
CORS_ORIGINS=https://your-domain.com

# 3. 生成 JWT 密钥
python -c "import secrets; print(secrets.token_urlsafe(32))"
# 将输出值填入 JWT_SECRET_KEY=

# 4. 启动 (安全检查通过后才会启动)
docker compose --profile app up -d
```

## 七、常见配置问题排查

### Q: 启动报 "生产环境安全检查失败"

```
原因: APP_ENV=prod 时触发了安全检查，存在不安全配置
排查:
1. JWT_SECRET_KEY 是否为空或使用了弱密钥
2. CORS_ORIGINS 是否为 *
3. RBAC_ADMIN_PASSWORD 是否为 admin123
4. RBAC_USER_PASSWORD 是否为空
```

### Q: 配置修改后不生效

```bash
# 1. 确认配置文件加载顺序
# Python: .env.local > .env
# Go: --env > .env.local > .env

# 2. 重启所有服务
docker compose down
docker compose up -d

# 3. 验证配置是否加载
python -c "from nexus.config import get_config; c = get_config(); print(c.llm.llm_model)"
```

### Q: .env.local 中的配置不生效

```bash
# 1. 确认文件名正确 (.env.local, 不是 .env.dev 或其他)
# 2. 确认文件在项目根目录
# 3. 确认 APP_ENV 未设置为 prod (prod 模式加载 .env.prod)
# 4. 检查文件编码 (UTF-8, 非 UTF-8-BOM)
```
