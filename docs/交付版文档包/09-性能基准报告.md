## 2. 基准指标定义

| 指标 | 说明 | 采集方式 |
|------|------|----------|
| 响应延迟 (P50/P95/P99) | 从请求到响应的端到端延迟 | Prometheus Histogram |
| QPS | 每秒请求数 | Prometheus Counter rate |
| 缓存命中率 | 语义缓存命中比例 | Cache Hits / (Hits + Misses) |
| Agent 调用延迟 | Supervisor + Experts + Responder 全链路延迟 | Langfuse Trace |
| LLM 调用延迟 | 单次 LLM API 延迟 | Prometheus Histogram |
| 并发连接数 | 当前活跃连接数 | Prometheus Gauge |

## 3. 基准测试结果

### 3.1 对话接口 (POST /chat)

| 场景 | P50 | P95 | P99 | QPS |
|------|-----|-----|-----|-----|
| 缓存命中 | ~50ms | ~80ms | ~100ms | 200+ |
| 闲聊 (LLM) | ~2000ms | ~3500ms | ~5000ms | 20 |
| 车控指令 (快速路径) | ~100ms | ~200ms | ~300ms | 100+ |
| 搜索类 (web_search) | ~3000ms | ~5000ms | ~7000ms | 15 |
| 工具类 (Tool→LLM 合成) | ~2500ms | ~4000ms | ~6000ms | 18 |

### 3.2 SSE 流式接口 (POST /chat/stream)

| 场景 | 首 Token | 完整响应 | P95 |
|------|----------|----------|-----|
| 缓存命中 | ~50ms | ~100ms | ~150ms |
| 闲聊 (流式) | ~500ms | ~3000ms | ~4500ms |
| 车控指令 | ~100ms | ~200ms | ~300ms |

### 3.3 Agent 链路延迟分解

| 节点 | 平均延迟 | 说明 |
|------|----------|------|
| Supervisor (记忆+路由+分派) | ~500ms | 含记忆召回 (Milvus+Neo4j) |
| Expert 并行执行 | ~200ms | 工具调用 + 车控 |
| Responder (LLM 生成) | ~1500ms | 依赖 LLM API 延迟 |
| Reflection (反思校验) | ~1000ms | 1 次 LLM 调用 |
| Reviewer (质量+记忆存储) | ~50ms (后台) | 异步执行，不阻塞 |

### 3.4 缓存性能

| 指标 | 值 | 说明 |
|------|-----|------|
| 缓存命中率 (稳态) | 30-50% | 取决于对话重复度 |
| 缓存查询延迟 | ~5ms | Redis RediSearch KNN |
| 缓存写入延迟 | ~10ms | Redis SETEX + 向量索引 |
| 副作用隔离 | 100% | 车控指令不缓存 |

### 3.5 Go 网关性能

| 指标 | 值 | 说明 |
|------|-----|------|
| Go 原生路由延迟 | ~2ms | 健康检查/中间件状态 |
| 代理转发延迟 | ~5ms | Go → Python 转发 |
| Prometheus 查询延迟 | ~50ms | dataplatform 并发指标 |
| 限流检查延迟 | ~1ms | Redis 滑动窗口 |

## 4. 性能瓶颈分析

### 4.1 LLM API 延迟 (主要瓶颈)

- **问题**: 云端 LLM API 调用占端到端延迟的 60-70%
- **影响**: 闲聊场景 P95 > 3.5s
- **缓解措施**:
  - 语义缓存 (命中率 30-50%，减少 LLM 调用)
  - 快速路径 (启发式路由，车控指令 <100ms)
  - 本地 LLM 降级 (降低网络延迟，增加 GPU 推理)
  - 流式输出 (降低首 Token 延迟)

### 4.2 记忆召回延迟

- **问题**: Milvus + Neo4j 三路融合检索 ~300ms
- **缓解措施**:
  - 快速路径跳过记忆召回 (车控指令)
  - Rerank 仅对 top-k 候选执行
  - 查询增强减少无效召回

### 4.3 反思校验延迟

- **问题**: LLM 反思增加 1 次额外 LLM 调用 (~1s)
- **缓解措施**:
  - `REFLECTION_ENABLED=false` 可关闭
  - 确定性日期校验 (正则，无需 LLM)
  - 轻量检查 (非空/长度) 跳过 LLM 调用

## 5. 压测方法

### 5.1 压测脚本

```bash
# 使用 chaos_test.py 进行混沌压测
cd backend_design
python scripts/chaos_test.py --concurrent 10 --duration 60

# 使用 test_api.py 进行功能测试
python scripts/test_api.py
```

### 5.2 Prometheus 指标查询

```promql
# QPS
sum(rate(nexus_requests_total[1m]))

# P95 延迟
histogram_quantile(0.95, sum(rate(nexus_request_latency_seconds_bucket[5m])) by (le))

# 缓存命中率
sum(rate(nexus_cache_hits_total[5m])) /
(sum(rate(nexus_cache_hits_total[5m])) + sum(rate(nexus_cache_misses_total[5m])))

# 当前并发
nexus_active_connections

# Agent 错误率
sum(rate(nexus_agent_invocations_total{status="error"}[5m])) /
sum(rate(nexus_agent_invocations_total[5m]))
```

### 5.3 Grafana 看板

预置 Grafana 看板包含:
- API 性能 (延迟 P50/P95/P99, QPS, 错误率)
- Agent 活动 (调用次数, 延迟, 各节点耗时)
- 缓存性能 (命中率, 查询/写入延迟)
- LLM 调用 (次数, 延迟, Token 用量)
- 系统资源 (CPU, 内存, GPU)

## 6. 性能优化建议

### 短期 (当前版本可做)

1. **关闭非必要反思**: `REFLECTION_ENABLED=false` 可减少 ~1s LLM 调用
2. **增大缓存 TTL**: `SEMANTIC_CACHE_TTL_SECONDS=7200` (2h) 提升命中率
3. **调整并发锁**: `SESSION_LOCKS_MAX=1000` 减少锁清理开销

### 中期 (下一迭代)

1. **本地 LLM 推理优化**: GPU 层调整、KV Cache 复用
2. **记忆召回缓存**: 热点查询的记忆结果缓存
3. **异步反思**: Reflection 节点异步化，不阻塞响应

### 长期 (架构演进)

1. **多节点水平扩展**: Redis 分布式 checkpoint + 多实例
2. **模型量化**: ASR/TTS 模型量化降低内存占用
3. **边缘部署**: 车机端本地推理 + 云端降级
