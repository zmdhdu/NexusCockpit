## 1. 硬件最低要求

| 组件 | 最低要求 | 说明 |
|------|----------|------|
| CPU | 4 核 x86_64 | ARM 架构需额外编译 PyTorch |
| 内存 | 8 GB | 含模型加载和 Docker 中间件 |
| 磁盘 | 50 GB SSD | 含模型文件 (~8GB) + Docker 镜像 (~15GB) |
| GPU | 无（CPU 推理） | ASR/TTS/LLM 均支持 CPU 模式，速度较慢 |
| 网络 | 千兆以太网 | 内网通信 + 云端 LLM API 调用 |
| 音频输入 | 麦克风阵列（USB/3.5mm） | 采样率 16kHz, 单声道 |
| 音频输出 | 扬声器/车载音响 | 3.5mm/蓝牙/HDMI |

## 2. 推荐配置

| 组件 | 推荐配置 | 说明 |
|------|----------|------|
| CPU | 8 核+ x86_64 | Intel i7/i9 或 AMD Ryzen 7/9 |

| GPU | NVIDIA GPU 8GB+ 显存 | 加速 ASR/TTS 推理, 本地 LLM 降级 |
| 操作系统 | Ubuntu 22.04 LTS | 生产环境推荐 Linux |
| Docker | 25.0+ | 容器化部署 |
| CUDA | 12.1 或 12.8 | GPU 加速依赖 |

## 3. GPU 适配说明

### 3.1 支持的 GPU 型号

| GPU 型号 | 显存 | 适用场景 | 推荐配置 |
|----------|------|----------|----------|
| NVIDIA RTX 3060 | 12GB | ASR+TTS+本地 LLM | 全 GPU 加速 |
| NVIDIA RTX 4060 | 8GB | ASR+TTS | 本地 LLM 需限制 GPU 层 |
| NVIDIA RTX 4090 | 24GB | 全功能+多实例 | 全 GPU 加速 |
| NVIDIA A10 | 24GB | 生产部署 | 全 GPU 加速 |
| 无 GPU | — | CPU 推理 | ASR ~2x实时, TTS ~3x实时 |

### 3.2 GPU 层配置

```bash
# 本地 LLM (llama.cpp) GPU 层数控制
LLAMA_CPP_GPU_LAYERS=-1   # -1=全部 GPU, 0=纯 CPU, N=前N层

# ASR/TTS 模型自动使用 GPU (如可用)
# 无需额外配置，PyTorch 自动检测 CUDA
```

### 3.3 CUDA 版本对应

| CUDA 版本 | PyTorch 安装命令 |
|-----------|-----------------|
| 12.1 | `pip install torch torchaudio --index-url https://download.pytorch.org/whl/cu121` |
| 12.8 | `pip install torch torchaudio --index-url https://download.pytorch.org/whl/cu128` |
| CPU | `pip install torch torchaudio --index-url https://download.pytorch.org/whl/cpu` |

## 4. 车机硬件对接

### 4.1 车控适配器模式

NexusCockpit 支持三种车控适配模式，通过 `VEHICLE_ADAPTER` 环境变量切换：

| 模式 | 配置值 | 适用场景 | 说明 |
|------|--------|----------|------|
| 模拟模式 | `mock` | 开发/演示/交付验收 | 内置 MockVehicleBus，无需真实车机 |
| HTTP 模式 | `http` | 对接外部 T-Box/网关 | 通过 HTTP API 与车控网关通信 |
| MCP 模式 | `mcp` | 对接 MCP 协议设备 | 通过 stdio 与 MCP 服务通信 |

### 4.2 HTTP 模式对接参数

```bash
VEHICLE_ADAPTER=http
VEHICLE_API_BASE_URL=http://<车控网关IP>:<端口>/api/v1
VEHICLE_API_TIMEOUT=10
```

### 4.3 CAN 总线对接说明

如需直接对接 CAN 总线，需在车控网关侧实现以下 HTTP 接口：

| 接口 | 方法 | 功能 |
|------|------|------|
| `/api/v1/climate` | POST | 空调控制（温度/风量/模式） |
| `/api/v1/windows` | POST | 车窗控制（开/关/位置） |
| `/api/v1/doors` | POST | 车门控制（开/锁） |
| `/api/v1/seats` | POST | 座椅控制（加热/通风/位置） |
| `/api/v1/navigation` | POST | 导航设置（目的地/路线） |
| `/api/v1/media` | POST | 媒体控制（播放/暂停/切换） |
| `/api/v1/status` | GET | 获取车辆完整状态 |

> 详细接口字段定义参见 [03-API接口协议文档](./03-API接口协议文档.md)。

## 5. 音频外设要求

### 5.1 麦克风要求

| 参数 | 要求 | 说明 |
|------|------|------|
| 采样率 | 16 kHz | ASR 模型要求 |
| 声道 | 单声道 | 多声道自动降混 |
| 位深 | 16-bit PCM | WAV 格式 |
| 信噪比 | ≥ 50 dB | 车载噪声环境建议 ≥ 60 dB |
| 麦克风阵列 | 推荐 2-4 麦 | 支持降噪和声源定位 |

### 5.2 扬声器要求

| 参数 | 要求 | 说明 |
|------|------|------|
| 输出格式 | WAV 22050 Hz | TTS 引擎默认输出 |
| 功率 | ≥ 10W | 车载环境 |
| 频响范围 | 100Hz - 10kHz | 语音频段 |

## 6. 常见硬件兼容性问题

### Q: GPU 不可用（`torch.cuda.is_available()` 返回 False）

```bash
# 1. 检查 GPU 驱动
nvidia-smi

# 2. 检查 CUDA 版本与 PyTorch 匹配
python -c "import torch; print(f'CUDA: {torch.version.cuda}, Available: {torch.cuda.is_available()}')"

# 3. 重新安装匹配版本的 PyTorch
pip install torch torchaudio --index-url https://download.pytorch.org/whl/cu121
```

### Q: 内存不足导致 OOM

```bash
# 1. 检查内存使用
docker stats

# 2. 减少 Docker 容器内存限制
# 编辑 docker-compose.yml 中的 deploy.resources.limits.memory

# 3. 使用 CPU 模式（降低内存占用）
# 确保 pip 安装的是 CPU 版本 PyTorch
```

### Q: 麦克风无声音输入

```bash
# 1. 检查麦克风设备
# Windows: 控制面板 → 声音 → 录制
# Linux: arecord -l

# 2. 测试录音
arecord -d 3 -f S16_LE -r 16000 test.wav

# 3. 确认采样率为 16kHz
```

### Q: ARM 架构（如树莓派）兼容性

ARM 架构需额外步骤：
1. 从源码编译 PyTorch（或使用预编译 ARM 版本）
2. FunASR/CosyVoice 模型需确认 ARM 兼容性
3. Docker 镜像需使用 `arm64v8/` 前缀版本
4. 性能预期：ASR/TTS 推理速度约为 x86 的 1/3-1/2
