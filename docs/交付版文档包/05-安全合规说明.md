## 1. 安全架构概述

NexusCockpit 采用 **多层纵深防御** 策略:

```
┌──────────────────────────────────────────────────────┐
│  前端 (Next.js)                                      │
│  - CORS 白名单                                       │
│  - JWT Token 存储 (httpOnly cookie)                  │
├──────────────────────────────────────────────────────┤
│  Go 网关 (NexusGate)                                 │
│  - JWT 鉴权 (双端共享密钥)                             │
│  - RBAC 角色控制 (admin / cockpit_user)              │
│  - 优先级限流 (Redis 滑动窗口)                        │
│  - WebSocket 安全握手                                │
├──────────────────────────────────────────────────────┤
│  Python 后端 (FastAPI)                               │
│  - 座舱级数据隔离 (cockpit_id)                        │
│  - 语义缓存副作用隔离                                 │
│  - 会话并发锁 (防历史污染)                             │
│  - 全局异常处理 (不泄露内部错误)                       │
├──────────────────────────────────────────────────────┤
│  数据层                                               │
│  - Redis (密码认证)                                   │
│  - MySQL (密码认证 + 座舱隔离)                         │
│  - Milvus / Neo4j (内网访问)                          │
└──────────────────────────────────────────────────────┘
```

## 2. 认证与授权

### 2.1 JWT 认证

- **算法**: HS256
- **密钥**: Python 和 Go 共享同一密钥 (`JWT_SECRET_KEY` / `JWT_SECRET`)
- **过期时间**: Python 1440 分钟 (24h)，Go 24 小时
- **Token 签发**: Go 网关签发，Python 验证

```bash
# 密钥配置 (生产环境必须设置强密钥)
JWT_SECRET_KEY=<至少32字符的随机字符串>
JWT_SECRET=<与 JWT_SECRET_KEY 相同的值>
```

### 2.2 RBAC 权限模型

| 角色 | 权限范围 |
|------|----------|
| `admin` | 管理员：用户管理、座舱注册、系统配置、查看聚合指标 |
| `cockpit_user` | 普通用户：语音对话、车控操作、查看个人数据 |

```bash
# RBAC 配置
RBAC_DEFAULT_ROLE=cockpit_user
RBAC_ADMIN_USERNAME=admin
RBAC_ADMIN_PASSWORD=<强口令>
RBAC_USER_PASSWORD=<共享口令，空=不校验(仅开发环境)>
```

### 2.3 座舱级数据隔离

- 每个座舱有独立的 `cockpit_id`
- 数据库查询按 `cockpit_id` 隔离
- Redis 按 `cockpit_id` 前缀隔离 key
- 管理员只能查看聚合指标，无法查看具体对话内容

## 3. 数据安全

### 3.1 数据分类

| 数据类别 | 存储位置 | 保护措施 |
|----------|----------|----------|
| 用户对话记录 | MySQL `chat_logs` | cockpit_id 隔离，管理员不可见内容 |
| 用户画像 | Neo4j | 用户 ID 关联，RBAC 控制 |
| 记忆向量 | Milvus | 内网访问，无公网暴露 |
| 缓存数据 | Redis | 密码认证，副作用隔离 |
| 声纹特征 | 文件系统 | 本地存储，无云端上传 |
| API Key | .env 文件 | 不纳入版本控制 |

### 3.2 缓存安全隔离

车控指令（如"打开车窗"）标记 `has_side_effect=True`，禁止写入缓存。
旧缓存条目在启动时自动清理 (`purge_vehicle_command_cache`)。

### 3.3 日志脱敏

- API Key 日志仅显示末 4 位 + 长度
- 用户输入日志截断到 200/2000 字符
- 对话内容不写入结构化日志 (仅写入 MySQL)

## 4. 网络安全

### 4.1 CORS 跨域

```bash
# 开发环境
CORS_ORIGINS=*                # 仅开发环境允许

# 生产环境 (必须指定具体域名)
CORS_ORIGINS=https://cockpit.example.com,https://admin.example.com
```

### 4.2 限流

- **算法**: Redis 滑动窗口
- **默认 QPS**: 100 (可配置 `RATE_LIMIT_QPS`)
- **超限响应**: HTTP 429 + `Retry-After: 60`

### 4.3 端口安全

| 服务 | 端口 | 暴露范围 |
|------|------|----------|
| Go 网关 | 8080 | 公网 |
| Python 后端 | 8000 | 内网 (通过网关代理) |
| 前端 | 3000 | 公网 (或通过 Nginx) |
| Redis | 16379 | 内网 |
| MySQL | 13306 | 内网 |
| Milvus | 19530 | 内网 |
| Neo4j | 17687 | 内网 |
| Prometheus | 9200 | 内网 |

## 5. 生产环境安全检查

### 5.1 自动检查机制

`APP_ENV=prod` 时，系统启动前自动检查以下安全配置:

| 检查项 | 不通过条件 | 处理 |
|--------|------------|------|
| JWT 密钥 | 使用默认值 `nexus-cockpit-secret` | **拒绝启动** |
| 管理员口令 | 使用弱口令 `admin123` | **拒绝启动** |
| CORS | 使用 `*` 通配符 | **拒绝启动** |
| 用户口令 | `RBAC_USER_PASSWORD` 为空 | **拒绝启动** |

### 5.2 检查代码位置

- Python: `backend_design/nexus/config.py` → `validate_prod_security()`
- Go: `backend_design/nexus_gate/internal/config/config.go` → `validateProdSecurity()`

## 6. 合规性声明

### 6.1 数据隐私

- NexusCockpit 不上传用户数据到第三方服务
- 所有数据存储在本地 Docker 容器或用户配置的私有云
- LLM API 调用仅发送当前对话内容，不发送历史数据

### 6.2 开源协议

- 项目使用 **MIT License** 开源
- 第三方依赖遵循各自协议

### 6.3 数据保留

- 日志数据默认保留 30 天，过期自动清理
- 用户可通过 `DATA_RETENTION_DAYS` 配置保留天数
- 清理操作由 `DataRetentionManager` 后台执行

### 6.4 声纹数据

- 声纹特征文件存储在本地 `assets/speaker/` 目录
- 不上传到云端
- 用户可随时删除声纹注册文件

## 7. 安全最佳实践

### 7.1 密钥管理

```bash
# 生成强随机密钥
openssl rand -hex 32

# 或使用 Python
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

### 7.2 .env 文件保护

```bash
# 确保 .env 文件不被 Git 跟踪
echo ".env*" >> .gitignore

# 设置文件权限
chmod 600 .env.local .env.prod
```

### 7.3 Docker 安全

```bash
# 使用非 root 用户运行容器
# docker-compose.yml: user: "1000:1000"

# 限制容器资源
# deploy.resources.limits.memory: 4G
# deploy.resources.limits.cpus: "2"
```

### 7.4 网络隔离

```bash
# 生产环境建议使用 Docker 内部网络
# 公网仅暴露 8080 (Go 网关) 和 3000 (前端)
# 其余服务使用 internal: true
```

## 8. 安全事件响应

### 8.1 应急流程

1. **发现**: 监控告警 / 用户反馈 / 日志异常
2. **隔离**: 停止受影响服务
3. **评估**: 检查日志确定影响范围
4. **处理**: 修复漏洞 / 重置密钥 / 清理数据
5. **恢复**: 重启服务并验证
6. **复盘**: 记录事件并改进安全措施

### 8.2 密钥泄露处理

```bash
# 1. 立即更换所有密钥
# JWT_SECRET_KEY, RBAC_ADMIN_PASSWORD, REDIS_PASSWORD 等

# 2. 清理旧 Token (Redis)
redis-cli FLUSHDB  # ⚠️ 谨慎操作

# 3. 重启所有服务
docker compose restart
```

### 8.3 数据泄露处理

```bash
# 1. 停止服务
docker compose down

# 2. 检查数据访问日志
docker compose logs nexus_ai | grep "suspicious"

# 3. 通知相关用户 (如有用户数据泄露)

# 4. 修复漏洞后重启
docker compose up -d
```
