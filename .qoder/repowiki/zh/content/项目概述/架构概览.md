## 引言
本文件为 NexusCockpit 的架构概览，面向开发者与运维人员，系统性阐述 7 层分层架构（L0-L7）的职责边界、组件关系与数据流；详解 Multi-Agent 工作流（Supervisor + 5 Expert Agents）的设计与执行流程；解释 GraphRAG 三路融合检索（向量+图谱+全文）的实现要点；并说明 Go 并发网关与 Python AI 服务的协作模式。文末提供系统上下文图、组件交互图与关键数据流图，帮助快速建立整体视图。

## 项目结构
NexusCockpit 采用前后端分离与多语言服务组合：
- 前端：Next.js 应用，提供座舱控制台、聊天、数据中台等页面
- 后端：Python FastAPI 服务承载 Agent、RAG、技能、ASR/TTS、MCP 等能力
- 网关：Go 高并发网关，负责鉴权、限流、WebSocket Hub 与反向代理
- 基础设施：Docker Compose 编排 Milvus、Neo4j、Redis、MySQL、Prometheus、Grafana

### 7 层分层架构（L0-L7）
- L0 基础设施层：容器化部署 Milvus、Neo4j、Redis、MySQL、Prometheus、Grafana，支持双模式（本地/云端）
- L1 核心层：配置中心、结构化日志、异常体系、熔断器、JWT 认证、个性化服务
- L2 数据层：GraphRAG 引擎、记忆系统、数据模型（状态/Schema）
- L3 服务层：ASR/TTS、Skills、Vehicle、Intent、MCP
- L4 Agent 层：Supervisor + 5 Expert Agents + Responder + Reflection + Reviewer
- L5 中间件层：语义缓存、限流、会话存储、异步任务、熔断器
- L6 API 层：FastAPI REST/SSE/WebSocket、统一错误格式、CORS、指标挂载
- L7 可观测层：Langfuse 追踪、Prometheus 指标、Grafana 面板

### Multi-Agent 工作流（Supervisor + 5 Expert Agents）
- 入口：SupervisorGraph 编排 LangGraph StateGraph，定义节点与边
- 节点：SupervisorNode（记忆召回+意图路由+专家分派）、DispatchNode（并行执行）、ResponderNode（汇总+LLM 合成）、ReflectionNode（事实性/一致性/幻觉检查）、ReviewerNode（质量检查+记忆存储）
- 专家：Vehicle、Navigation、Lifestyle、Health、Chat 五类专家，基于 SkillRegistry 调用具体技能
- 输出：全链路强制闭环，所有分支均经过 Reflection + Reviewer + Output Gateway 校验

### GraphRAG 三路融合检索（向量+图谱+全文）
- 三路召回：Milvus 向量检索、Neo4j 图谱关系遍历、BM25 全文匹配
- 融合策略：RRF（Reciprocal Rank Fusion）对三路结果进行加权排序
- 重排：bge-reranker-v2-m3 对 Top-N 结果进行二次重排
- 使用场景：用户记忆召回、食材库检索、混合查询

```mermaid

G --> F
B --> F
F --> R["Rerank(bge-reranker-v2-m3)<br/>Top-K 重排"]
```

## 依赖关系分析

- 外部依赖：
  - Go 网关与 Python 服务共享 JWT 密钥
  - ASR/TTS 模型文件位于 models/ 目录，按需加载
  - 中间件通过 Docker Compose 管理

## 性能考量
- 并发与流式：Go 网关高并发低内存；Python 侧 SSE 流式输出，GenerationTaskPool 将 pipeline 与 SSE 连接解耦，客户端断连不中断生成
- 缓存与降级：Redis 语义缓存（副作用隔离）、LLM 自动降级（云端→本地 llama.cpp）、向量/图谱连接失败不阻塞启动
- 资源预热：ASR/TTS 模型后台预加载，避免阻塞启动；Checkpoint SQLite 持久化 Agent 状态
- 指标与监控：Prometheus 指标采集覆盖 API 延迟、Agent 耗时、缓存命中率；Grafana 可视化看板

## 故障排查指南
- 常见问题定位：
  - JWT 不一致：确认 Go 网关与 Python 服务使用相同 JWT_SECRET_KEY
  - Milvus/Neo4j 不可用：启动阶段记录警告，运行时降级处理；检查端口与网络
  - LLM 不可用：触发 429 错误短路，走完整 Reviewer + Output Gateway 兜底
  - 语义缓存命中导致车控指令未执行：启动时清理旧缓存条目
- 诊断工具：
  - 健康检查：/health（Python）、/health（Go）
  - 指标端点：/metrics（Prometheus）
  - 日志：结构化日志文件、Go 网关日志文件

## 结论
NexusCockpit 以清晰的 7 层分层架构为基础，结合 Multi-Agent 协同与 GraphRAG 融合检索，构建了高可用、可扩展的车载语音 Agent 平台。Go 网关与 Python 服务分工明确，前者专注高并发与安全控制，后者聚焦 AI 能力与业务编排。通过完善的可观测性与降级策略，系统在复杂车载场景中具备稳健的运行表现与良好的扩展性。

## 附录
- 技术选型权衡：
  - FastAPI：异步原生、自动文档，适合 AI 服务
  - LangGraph：有状态图与条件路由，适合 Agent 编排
  - Milvus/Neo4j：开源、生态完善，支持本地与云端双模式
  - Redis：语义缓存与限流，轻量高效
  - bge-reranker-v2-m3：高质量重排，提升检索效果
  - Gin/gorilla/websocket：高并发与 WebSocket 支持
  - Next.js/Zustand/Tailwind：现代前端栈，开发体验佳
