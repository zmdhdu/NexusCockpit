## 简介
本技术栈文档面向 NexusCockpit 开发者，系统梳理后端（Python FastAPI、LangGraph、Pydantic）、前端（Next.js 14、React、Tailwind CSS）与基础设施（Docker、Milvus、Neo4j、Redis、MySQL、Prometheus/Grafana/Loki/Langfuse）的技术选型、版本要求与兼容性。同时覆盖开发工具链（Makefile、pre-commit、linting）、多语言混合架构（Python + Go）的协作模式与通信机制，以及依赖管理、包管理与构建流程的最佳实践，帮助快速完成环境搭建与问题定位。

## 项目结构
NexusCockpit 采用前后端分离与多服务编排：
- 后端 Python（FastAPI）：AI Agent、RAG、车控技能、会话与中间件等
- 网关 Go（Gin）：鉴权、限流、WebSocket、反向代理到后端
- 前端 Next.js：控制台、聊天、座舱控制、数据平台等页面
- 基础设施：Milvus（向量）、Neo4j（图谱）、Redis（缓存/限流/会话）、MySQL（持久化）、Langfuse（LLM 追踪）、Prometheus/Grafana/Loki（指标/日志/可视化）

## 架构总览
NexusCockpit 采用“前端 → Go 网关 → Python 后端 → 基础设施”的分层架构。网关承担鉴权、限流、WebSocket 转发与统一入口；后端承载 AI Agent、RAG、车控技能与业务逻辑；基础设施提供向量、图谱、缓存、关系型数据库与可观测性能力。

## 详细组件分析

### 后端（Python FastAPI + LangGraph + Pydantic）
- 启动与生命周期
  - FastAPI 应用通过 lifespan 初始化日志、指标、Embedding、向量/图谱存储、车控适配器、语义缓存、会话存储、限流器、Langfuse 监控与 Agent 工作流
  - 关键入口文件负责注册路由、中间件与异常处理
- Agent 与 RAG
  - 使用 LangGraph StateGraph 编排 Supervisor + 专家 Agent 的多智能体流程
  - RAG 链路：文本切分 → Embedding（本地 bge-m3）→ Milvus 向量检索 → Neo4j 图谱召回 → Reranker → 生成
- 配置与校验
  - Pydantic Settings 集中管理环境变量与默认值，确保强类型校验
- 中间件
  - Redis 语义缓存（基于 Embedding 相似度命中）、会话历史持久化、分布式限流
- 可观测性
  - Prometheus 指标暴露、Langfuse LLM 调用追踪、结构化日志

## 依赖与构建流程
- 后端（Python）
  - 依赖管理：pyproject.toml 与 requirements.txt 双轨声明，严格锁定关键库版本
  - 构建镜像：多阶段构建，CPU-only PyTorch 显著减小镜像体积
  - 启动命令：uvicorn 运行 FastAPI 应用
- 网关（Go）
  - 依赖管理：go.mod 固定版本，静态编译 CGO_ENABLED=0
  - 构建镜像：builder 编译二进制，runner 仅含运行时依赖
- 前端（Next.js）
  - 依赖管理：package.json + package-lock.json
  - 构建镜像：builder 安装依赖并构建，runner 仅包含 .next/standalone 产物
- Makefile 统一入口
  - 安装：install（后端）、install-gpu（GPU PyTorch）、install-frontend、install-gateway、install-all
  - 开发：dev、dev-frontend、dev-all、带日志捕获的 dev-log 系列
  - 质量：lint（ruff/go vet）、format、check（lint + mypy + pytest + go build）
  - 测试：test、test-cov
  - 清理：clean
  - 数据库初始化：init-db（Milvus/Neo4j）

## 故障排查指南
- 常见启动问题
  - Milvus/Neo4j 连接失败：后端启动时记录错误但不阻塞，需检查 docker-compose 健康检查与服务端口映射
  - Redis 认证失败：确认 REDIS_PASSWORD 与容器内 requirepass 一致
  - MySQL 字符集/认证：确保 utf8mb4 与 mysql_native_password 插件启用
- 网关与后端通信
  - 确认 NEXUS_AI_HOST/NEXUS_AI_PORT 环境变量正确指向 nexus_ai:8000
  - 检查 CORS 与跨域策略（前端直连 8080 网关）
- 前端构建与运行
  - NEXT_PUBLIC_API_URL 指向网关地址（默认 http://localhost:8080）
  - standalone 构建产物需 node 运行时，确保端口 3000 未被占用
- 日志定位
  - 后端：logs/backend_logs/*（PowerShell 脚本捕获）
  - 前端：logs/frontend_logs/*（next.config.js 在开发环境写入）
  - 网关：容器标准输出，可通过 docker logs 查看

## 结论
NexusCockpit 以 FastAPI + LangGraph 为核心构建车载多智能体与 RAG 能力，Go 网关提供高性能鉴权与实时通信，Next.js 前端提供现代化交互体验。依托 Docker Compose 编排 Milvus、Neo4j、Redis、MySQL 与可观测性栈，形成完整的企业级解决方案。通过 Makefile 与 pre-commit 规范开发与质量流程，保障代码一致性与可维护性。

## 附录：环境搭建与最佳实践
- 环境准备
  - Python ≥ 3.10；Node ≥ 18；Go ≥ 1.22；Docker 与 Docker Compose
- 安装依赖
  - 后端：make install 或 make install-gpu（GPU 版）
  - 前端：make install-frontend
  - 网关：make install-gateway
- 启动基础设施
  - docker compose up -d
- 初始化数据库
  - make init-db（Milvus/Neo4j）
- 开发调试
  - 后端：make dev 或 make dev-log
  - 前端：make dev-frontend 或 make dev-frontend-log
  - 网关：make dev-gateway-log
- 代码质量
  - lint：make lint（ruff + go vet）
  - format：make format
  - check：make check（lint + mypy + pytest + go build）
- 依赖与版本管理
  - Python：pyproject.toml + requirements.txt 锁定版本，避免漂移
  - Node：package-lock.json 锁定依赖树
  - Go：go.mod/go.sum 固定模块版本
- 构建与发布
  - 后端：CPU-only PyTorch 镜像，减少体积
  - 前端：standalone 输出，最小运行时
  - 网关：静态编译，无 CGO 依赖
