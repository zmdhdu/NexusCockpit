## 引言
本文件面向架构师与高级开发者，系统化阐述 NexusCockpit 的 7 层分层架构（L0-L7），深入解释各层职责、组件交互与数据流向；重点剖析 Multi-Agent 工作流（Supervisor + 5 专家 Agent）、GraphRAG 三路融合检索（向量+图谱+全文）以及车控系统三模式适配（Mock/HTTP/MCP）。文档包含架构图、组件关系图与关键数据流图，并总结技术决策、权衡与约束。

## 项目结构
NexusCockpit 采用前后端分离与多模块组织：后端以 Python FastAPI 为主，Go 网关提供前置转发与鉴权；前端基于 Next.js 构建座舱控制台与运营看板。后端按 L0-L7 分层组织，Agent、RAG、Skills、Vehicle、Intent、Middleware、API、Observability 等子系统清晰解耦。

## 核心组件
- 应用入口与生命周期管理：FastAPI 应用创建、全局中间件、异常处理、资源初始化与清理。
- Multi-Agent 编排：Supervisor 调度器 + 5 个专家（车辆、导航、生活、健康、聊天）+ Responder + Reflection + Reviewer。
- GraphRAG 检索：向量（Milvus/Zilliz）、图谱（Neo4j/AuraDB）、BM25 全文检索三路召回，RRF 融合与 Rerank 重排。
- 车控适配器：Mock/HTTP/MCP 三模式统一抽象，支持多座舱隔离与参数安全校验。
- 中间件能力：Redis 语义缓存（KNN）、滑动窗口限流、会话持久化、异步任务。
- 可观测性：Langfuse 追踪、Prometheus 指标、Grafana 面板、结构化日志。

### L2 数据层（Data）— GraphRAG 三路融合
- 职责：Embedding、向量库、知识图谱、BM25 全文检索、Rerank、Cherry 知识库、统一检索路由。
- 关键点：
  - 三路召回：向量（Milvus/Zilliz）、图谱（Neo4j/AuraDB）、BM25（langchain-community.BM25Retriever）。
  - 融合策略：RRF（Reciprocal Rank Fusion）排序。
  - 重排：bge-reranker-v2-m3 或硅基流动 API。
  - 渐进式披露与用户习惯注入。

### L4 Agent 层（Multi-Agent）
- 职责：Supervisor 调度 + 5 专家并行 + Responder 汇总 + Reflection 反思 + Reviewer 审查。
- 关键点：
  - 状态管理：TypedDict + Annotated reducer（列表拼接/字典合并）。
  - 并行执行：asyncio.gather 同时调用活跃专家。
  - 防漂移与安全：车控指令强制路由 vehicle 专家，沙箱枚举校验，副作用标记禁止缓存。
  - 流式优化：先生成完整回复 → 校验 → 再发送，防止未校验内容呈现。

## 性能考量
- GraphRAG 三路召回 + RRF 融合 + Rerank 提升召回精度与相关性，但增加延迟；可通过关闭 BM25/Rerank 降级。
- Redis 语义缓存使用 KNN 向量检索 O(log n)，显著降低重复查询延迟；副作用隔离避免车控指令误命中。
- Agent 并行执行减少端到端时延；流式“先完整生成后校验”保障用户体验与安全性。
- 中间件限流保护后端；熔断器保护外部 LLM/云服务。

## 故障排查指南
- 启动阶段：检查 LLM API Key、Milvus/Neo4j/Redis 连接；若失败记录警告但不阻塞启动。
- 缓存问题：确认 RediSearch 可用性与相似度阈值；车控指令 has_side_effect=True 不应命中缓存。
- Agent 路由：核查意图路由优先级与防漂移机制；检查 SkillGroup 分组与工具名匹配。
- 车控适配：验证 VEHICLE_ADAPTER 配置与 MCP 命令解析；Mock 模式下多座舱状态隔离。
- 可观测性：查看 Langfuse 追踪链路与 Prometheus 指标定位瓶颈。

## 结论
NexusCockpit 通过清晰的 7 层分层架构实现了高内聚、低耦合的系统设计。Multi-Agent 工作流提升了复杂任务的协同处理能力；GraphRAG 三路融合检索兼顾语义理解与精确匹配；车控三模式适配满足开发与生产环境的灵活切换。结合中间件与可观测性能力，系统在稳定性、性能与可维护性方面具备工程级水准。
