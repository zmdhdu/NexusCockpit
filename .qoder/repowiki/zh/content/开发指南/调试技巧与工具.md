## 简介
本指南面向 NexusCockpit 项目的开发者，提供从 Python 后端、Go 网关到前端应用的系统化调试方法与工具使用建议。内容涵盖：
- Python FastAPI 服务：IDE 调试配置、结构化日志、异常统一处理、Prometheus 指标采集
- Go 网关：启动流程、环境变量加载、日志输出、限流与代理链路追踪
- 前端应用：浏览器开发者工具、网络请求调试、Zustand 状态管理调试
- Docker 容器：多服务编排、健康检查、开发模式端口暴露、日志收集（Loki/Prometheus/Grafana）
- 数据库与中间件：MySQL、Redis、Milvus、Neo4j 的常见连接问题与优化思路
- 性能瓶颈定位：内存泄漏检测、慢查询分析、并发与限流调优

## 项目结构
NexusCockpit 采用“Go 网关 + Python AI 后端 + Next.js 前端”的分层架构，并通过 Docker Compose 编排基础设施（Redis、MySQL、Milvus、Neo4j、Langfuse、Prometheus、Grafana、Loki）。

## 详细组件分析

### Python 后端调试要点
- 启动与热重载
  - 本地运行：通过 uvicorn 启动，支持 --reload 热重载；Windows 可使用 PowerShell 脚本将终端输出同时写入日志文件
  - 容器运行：Dockerfile 中设置健康检查与健康探测，便于编排平台感知服务就绪
- 结构化日志与异常处理
  - 使用 structlog 输出 JSON（生产）或彩色控制台（开发），自动脱敏敏感字段
  - 全局异常处理器统一错误格式，便于前端一致化处理
- 指标与可观测性
  - Prometheus 指标挂载于 /metrics，中间件统计请求计数与延迟
  - Langfuse 用于 LLM 调用追踪（可选）
- 配置与环境
  - AppConfig 聚合所有子系统配置，支持 .env 文件与环境变量覆盖

## 性能考虑
- Python 后端
  - 中间件统一计时与指标记录，关注 /metrics 中的 REQUEST_COUNT 与 REQUEST_LATENCY
  - ASR/TTS 模型后台预加载，避免阻塞启动；首次请求按需加载
  - 结构化日志在生产环境输出 JSON，减少 I/O 开销；敏感字段脱敏
- Go 网关
  - 令牌桶限流保护后端；合理设置 QPS 上限
  - 日志文件轮转与集中输出，便于快速定位瓶颈
- 前端
  - 使用浏览器性能面板分析首屏渲染与网络请求耗时
  - Zustand 状态变更尽量批量更新，避免频繁重渲染
- 数据库与中间件
  - MySQL：慢查询日志、索引优化、连接池配置
  - Redis：内存策略 allkeys-lru、最大内存限制、IO 线程数
  - Milvus/Neo4j：连接失败不阻止启动，运行时重试与降级

## 故障排查指南
- Python 后端
  - 启动失败：检查 .env 配置、依赖安装、端口占用；查看 logs/backend_logs/*.log
  - 认证失败：确认 JWT_SECRET 与网关一致；查看 AuthError 处理器日志
  - 限流触发：检查 RATE_LIMIT_QPS 与客户端请求频率；查看 RateLimitError 处理器
  - 指标缺失：确认 /metrics 端点可达；检查 Prometheus 抓取配置
- Go 网关
  - 启动警告：检查 .env.local/.env 是否加载成功；确认 NEXUS_AI_HOST/NEXUS_AI_PORT
  - 代理失败：验证 Python 后端健康检查；查看 gateway_*.log
  - 限流拒绝：调整 QPS；观察限流器日志
- 前端
  - 跨域错误：检查 CORS_ORIGINS 与 NEXT_PUBLIC_API_URL
  - 状态不同步：查看 Zustand DevTools（浏览器扩展）与 localStorage
  - 网络请求失败：使用 Network 面板查看请求头、响应码与错误信息
- Docker 与基础设施
  - 健康检查失败：检查服务端口映射、依赖服务就绪顺序
  - 日志收集：确认 Loki/Grafana 端口暴露与配置文件挂载
  - 数据库连接：检查密码、字符集、端口映射与防火墙规则
