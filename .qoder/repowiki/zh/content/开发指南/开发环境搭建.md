## 详细组件分析

### Python 后端环境搭建（含 CPU/GPU PyTorch）
- 使用 Makefile 一键创建虚拟环境并安装依赖：
  - CPU 版本：make install
  - GPU 版本（CUDA 12.1）：make install-gpu
- 也可手动操作：
  - 创建 venv：python -m venv .venv
  - 激活 venv（Windows）：.venv\Scripts\activate
  - 安装 PyTorch（CPU）：pip install torch torchaudio --index-url https://download.pytorch.org/whl/cpu
  - 安装 PyTorch（GPU cu121）：pip install torch torchaudio --index-url https://download.pytorch.org/whl/cu121
  - 安装其他依赖：pip install -r backend_design/requirements.txt
- 运行后端：
  - 直接运行：make dev
  - 带日志捕获（PowerShell）：make dev-log

注意：
- requirements.txt 中明确说明需先单独安装 PyTorch，再安装其余依赖。
- pyproject.toml 声明了 Python>=3.10 及主要依赖版本范围。

- 前后端共享 .env（或 .env.local），用于 JWT、数据库密码、Redis 密码等。

## 性能注意事项
- 镜像体积优化：Python 后端 Dockerfile 使用 CPU-only PyTorch 与 slim 基础镜像，显著减小镜像大小。
- 分层缓存：Docker 构建阶段将依赖安装与源码复制分离，提升构建速度。
- 资源限制：Redis 设置了 maxmemory 与淘汰策略，避免内存溢出。
- 健康检查：各服务均配置 healthcheck，便于编排与自愈。

## 故障排查指南
常见问题与解决思路：
- 端口冲突（Windows Hyper-V 保留范围）
  - Redis 使用 16379，MySQL 使用 13306，Neo4j 使用 17687，避免与系统保留端口冲突。
- 依赖安装失败
  - 确认 Python 版本 >= 3.10；先安装 PyTorch（CPU/GPU）再安装 requirements.txt。
  - 前端若网络问题，可使用国内镜像源或离线包。
- 数据库/中间件未就绪
  - 使用 make docker-logs 查看服务状态；确保 healthcheck 通过后再启动应用。
- 环境变量不一致
  - 确保 .env/.env.local 中的 JWT 密钥、Redis/MySQL/Neo4j 密码前后端一致。
- 日志定位
  - 使用 PowerShell 脚本启动的服务会将输出写入 logs 目录下对应日志文件。
