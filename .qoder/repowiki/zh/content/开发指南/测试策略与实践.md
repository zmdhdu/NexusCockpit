## 引言
本指南面向 NexusCockpit 项目的测试策略与最佳实践，覆盖单元测试、集成测试、端到端测试、覆盖率与报告、性能/压力/安全测试方法，以及持续集成配置。目标是帮助团队以 pytest 为核心构建稳定、可维护、可观测的测试体系，确保代码质量与功能稳定性。

## 核心组件
- 测试框架与运行环境
  - pytest、pytest-asyncio、pytest-cov（可选）在 pyproject.toml 中声明，测试路径为 tests。

## 性能考虑
- 测试性能优化
  - 使用 ASGI 直连测试避免进程启动开销。
  - 合理拆分测试集，避免共享全局状态污染。
  - 对耗时操作（网络、模型加载）进行 Mock 或缓存。
- 覆盖率目标
  - 建议核心模块（Agent、意图路由、车控总线、会话管理）达到 80%+ 行覆盖率。
  - 报告生成：pytest-cov 输出 HTML 与终端摘要。
- 性能/压力测试
  - 使用 locust/k6 对 API 进行压测，关注 QPS、延迟分布、错误率。
  - 对 LLM/向量检索等慢路径进行降级与限流测试。
- 安全测试
  - 注入非法参数、越权访问、JWT 伪造、SQL 注入等用例。
  - 依赖扫描（pip-audit）、镜像漏洞扫描（Trivy）。

## 故障排查指南
- 常见问题
  - 异步测试未启用：确保 pytest.ini_options 中 asyncio_mode=auto 或使用 @pytest.mark.asyncio。
  - 依赖缺失：CI 仅安装轻量依赖，本地需安装完整 dev 依赖。
  - 上下文污染：每个测试独立实例化管理器/上下文，避免单例污染。
- 定位技巧
  - 增加日志输出（structlog），捕获请求/响应与中间状态。
  - 使用 pytest -v -s 查看详细输出，结合 --tb=short 聚焦错误堆栈。
  - 对失败用例最小化复现，逐步缩小范围。

## 附录

### 测试清单与最佳实践
- 单元测试
  - 每个类/函数至少一个正向用例与一个异常用例。
  - 使用 fixture 管理测试数据与依赖，避免硬编码。
  - 对异步代码使用 pytest-asyncio，避免阻塞。
- 集成测试
  - 使用 ASGI 直连或 TestClient，减少外部依赖。
  - 对数据库/缓存/外部服务使用 Mock 或内存实现。
- 端到端测试
  - 覆盖关键用户旅程（登录、聊天、车控）。
  - 使用稳定的测试账号与数据快照。
- 覆盖率与报告
  - 目标：核心模块≥80%，整体≥70%。
  - 报告：HTML + 终端摘要，CI 中归档。
- 持续集成
  - 分支保护：必须通过 lint、类型检查、测试。
  - 并行执行：按模块拆分任务，缩短反馈时间。
